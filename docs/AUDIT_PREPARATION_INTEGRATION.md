# v52 账表准备界面集成合同

`AuditPreparation.mount(host, ctx)` 只使用当前项目资料清单中的 Excel 附件。`ctx` 提供 `key`、`getRecord()`、`isCurrent()`、`run(fn)`、`save(patch)`；返回的 `destroy()` 必须在离开阶段或切换项目时调用。`run` 应串行执行并暂时禁止界面切换；`save` 必须继续使用工作区 IndexedDB 原有 revision CAS 与 `WorkpaperGovernance.assertTransition`，不能换成无条件覆盖。

## 明确范围

- 序时账、末级科目余额表、余额式未审资产负债表的来源、可见工作表、原列、完整行区间和范围必须人工确认。每份最多 20,000 行；整行空白及重复映射列拒绝，不静默忽略。
- 主体使用人工填写的 `entityId`。金额单位是明确的文本值，支持“元”“万元”等，但所有资料共同使用所确认单位；不会自动推断或换算。小数位必须明确为 0—6，空白不当成 0。
- 原 Excel 公式仅使用缓存值，不计算公式、不验证缓存是否已刷新。Excel 日期序号、不明金额、非标准日期不会被猜测转换成符合条件的数据；应由操作者核实原导出格式。
- 本页不自动证明资料完整性和真实性，不处理利润表、现金流量表及需要业务调整/重分类的财报映射，不形成审计意见。

## 变化与写入

1. 修改来源、工作表、列或行范围会撤销相关人工确认；改变作用域会撤销三个数据集确认；报表科目映射变化会撤销映射确认。旧结果不再作为本页写入依据，但原保存记录不会被静默删除。
2. 校验保存 `input`、`result`、`sourceRefs`、`inputHash`、`columnMappings`、`mappingHash`、`calculatedAt`。`inputHash` 是规范输入 JSON 的 SHA256；`mappingHash` 单独绑定原工作表、行区间和列号，避免换列但金额相同而沿用旧确认。
3. 建议使用前重新执行纯引擎，并比较输入、映射和来源绑定。三个资料项须仍为 `confirmed`，原附件下载须通过实际哈希核验。
4. 目标只使用 `WorkpaperRouting.fields` 过滤后的完整可见空白字段；`answerKeys` 必须定位唯一真实存储地址。Excel 还读取哈希匹配的原目标工作簿，拒绝隐藏工作表、非空原单元格、公式、数组区域与链接。禁止改写已有填写、已有自动来源记录和冻结范围。
5. 耗时目标准备和读取后，再核对原资料 revision/代次/hash/status，最后检查页面/项目仍有效、工作区原 revision 及人工选择未变，然后调用工作区 CAS 保存。任何失败均不发起替代性无条件写入。
6. 每次成功只写一个明确选择的字段及其 `autoFillProvenance`，保持 `pending-review`；含原资料绑定、输入/映射哈希、实际目标 sheet/answerKey，以及财务数据的原工作表单元格。人工范围字段明确标识 `manual-scope`，不冒充从账表识别的内容。真实字符串 `"0.00"` 可以填入，空白不能充当零。

## 并发与可信边界

资料库与工作区是两个独立的浏览器 IndexedDB 数据库；**本版没有跨库原子事务或服务器分布式锁**。最终资料检查绑定其读取快照，工作区 CAS 防止并发覆盖，但不能宣称资料检查与另一库提交之间具有全局可串行化保证。事务所使用时仍须控制项目资料编辑并发，并在复核时核对来源绑定；此功能是本机防误改，不是不可篡改凭证或正式审计授权。

仅技术校验及待复核建议被保存。本页不会自动核对底稿、解除冻结、关门归档或改变原模板。

## 专项测试范围

`tests/audit-preparation.test.cjs` 在独立浏览器上下文运行真实 XLS/XLSX 解析 Worker、实际资料库和工作区 IndexedDB、真实纯校验及治理模块。仅与本任务无关的 ZIP 库边界使用合成且哈希绑定的目标 fixture；因此测试不冒充真实客户账套或真实原包整体验收。

覆盖正常写入与刷新后读取、缺金额、未核对资料、资料及工作区并发变化、页面销毁、普通/复合字段防覆盖、实际冻结、空来源、整空行、隐藏目标、并行来源加载、重复列、确认失效、单位与空精度、实际原公式/原文字禁止改写及零值来源定位。专项禁止远程请求并检查页面运行错误；未跑全量测试。
