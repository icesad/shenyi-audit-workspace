# v0.1 本机备份合并预览模块

`dist/backup-restore.js` 是只做合并预览的纯函数模块。演示页面分别使用 v1/v2 备份信封和存储键；旧版本机数据先显式预览、用户确认后复制到 v2，原旧键不改写。页面提供文件选择、预览与确认后合并写入；异常原始 TXT 不可直接导入。功能经自动化测试，但尚未完成真实浏览器、生产持久化、事务所权限及业务验收。

## 接口

`QuoteBackup.previewBackup(backupText, currentRaw)` 接受 v0.1 导出的 JSON 文本（支持 UTF-8 BOM），及读取到的 localStorage 原始字符串；没有存储键时传 `null`。成功返回冻结后的对象：

- `expectedCurrentRaw`：预览时的原始存储值，调用方写入前必须再核对。
- `existingCount`、`incomingCount`、`addedCount`、`identicalCount`：明确预览数量。
- `mergedRecords`：新建的、递归冻结的完整合并结果，保留现有记录次序，新增记录追加。

纯预览模块接受 `app=hengdu-audit-quote`、`schema=1`、有效 `exportedAt` 与受支持的 v0.1 记录；页面先校验 v2 外层标识并在内部转换为该模块格式。v2 外部信封 `app=hengdu-audit-quote-v2`、`schema=2`，旧客户端不能导入。异常读取时提供的**原始存储数组**是抢救材料，不是此导入格式，必须先由维护人员分析，不能绕过校验直接导入。

两个记录 ID 相同且字段结构与数据完全相同（对象键顺序不计）时跳过；同 ID 不同内容、备份或本机内部重复 ID、坏格式、未知版本、污染字段、超过 10 MiB 或 5000 条等情况抛错，不产生部分结果。

## 集成边界

当前演示页面先让用户审阅数量并确认，再检查原始存储值与 `expectedCurrentRaw` 一致，才可一次性写入；写失败或容量不足须保留原值并显示错误。本机 `localStorage` 的检查和写入不是跨标签页原子事务，生产级并发需要事务型持久化。导入前应要求用户另存原始备份。敏感数据不应上传至未验收的第三方服务。

此模块只做结构校验和精确 ID 冲突检查，**不证明输入价格正确、来源可信或数据完整无篡改**。不提供真实性签名、权限、审计、财务规则核定，也不会验证或执行工作簿/宏；UI 展示来自文件的任何文本必须转义。
