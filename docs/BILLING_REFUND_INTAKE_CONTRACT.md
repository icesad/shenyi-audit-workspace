# 产品负责人退款受理

首版由产品负责人受理退款。负责人在绑定电脑登录后，可用原订单号查询年费或增购订单，核对原团队、金额、收款状态和是否已有支付异常。查询只返回处理该订单所需的账务信息。团队成员、团队技术管理员和其他审核身份没有受理入口及接口权限。

原收款已核验后，负责人可确认当前密码，登记受理原因和可选的支持单号。已受理订单可继续登记付款核对、待补资料、已联系反馈等跟进。每条记录保留责任账号、服务端时间和修订号，按从新到旧分页查询。提交原请求的重试复用同一条证据，另一笔提交抢先更新时须重新核对。表单只接收预设事项和长度受控的支持单号。

## 安全与存储

合成候选须显式启用 `billingSimulation.refundIntake: true`，并为独立审核账号配置 `billing.refund-intake` 授权。新库和升级均不默认授予权限。专用授权的历史持续参与普通业务角色、恢复及换机权限的隔离。查询和写入均依赖当前账号与绑定设备。密码验证之后和提交事务内会重新核对权限版本。撤权保留已登记历史。

桌面通过 `GET /api/auth/refund-intake/access` 检查是否可受理，并通过 `GET /api/platform/billing/refund-intakes/:kind/:orderId` 查原订单及历史。分页参数 `beforeRevision` 排除该修订。对同一个明确的订单路径 POST 时，服务端只接受请求编号、预期修订、事项、可选支持单号和当前密码。追加记录关联原订单及可信收款，历史不覆盖。

受理和跟进只写独立账本，已收款金额、订阅期限、席位、成员权利和支付异常继续由原流程维护。客户团队继续查阅和核对其已有订单。实际退款、处置已获权益、部分退款、生产身份授予和正式商户接入另行确认。
