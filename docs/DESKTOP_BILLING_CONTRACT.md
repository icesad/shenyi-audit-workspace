# 桌面订阅与席位

## 受管服务的微信 Native 官网付款

使用已绑定电脑登录的本团队技术管理员，打开「订阅与席位」中的「官网订单与微信支付」。在受管服务开启微信 Native 且配置报价目录时，选择团队年订阅或增购席位，再点「打开或继续本次购买」。系统浏览器打开受管 HTTPS 官网，用户可在网页核对报价、确认订单并生成付款码。

- 继续本次购买会沿用当前电脑保存的购买编号。若没有收到确认结果、浏览器退出或桌面重开，从同一入口继续即可。已锁原单保留其订单号、金额和付款截止。
- 同类型上一笔确认权益到账且无异常，或经核实已关单且未收款后，才可点「开始下一笔购买」。旧单状态不明时，继续到官网查同一笔原单。到期未获可信关单或仍在退款复核的订单，应保留供核对。
- 知道原订单编号时，可直接点「在官网打开原单」。仅配置原单付款的环境也提供该入口。

主进程按受管服务源、服务 UUID、当前账号、团队和购买类型隔离本地查询编号。每条记录只保存本次购买及已关联的上一笔查询编号。设备证明和短时网页票据由主进程处理。主进程按受信服务地址打开固定付款页，桌面界面只收到打开结果。桌面不接收价格目录，由官网负责展示报价和建单。 [官网订单接口](PAYMENT_CHANNEL_PREPARATION.md#官网报价和确认)

已通过设备核验的本团队技术管理员可以在「订阅与席位」查看订阅期限、已购席位、启用成员、邀请预留和可用名额，以及本团队合成订单。账务资格沿用服务端的技术管理资格，审计资料继续受各自的项目和模块权限约束。

续费默认沿用原到期前的已购席位。管理员可调整下一年数量，至少须覆盖已启用业务成员和仍有效的预留邀请。减席前须先释放足够名额。增购对齐原到期时刻，建单后显示服务端锁定的整单金额、数量与报价时效。现行候选计费参数见[年度续费合同](ANNUAL_SEAT_RENEWAL_CONTRACT.md)与[席位增购合同](SEAT_ADDITION_ORDER_CONTRACT.md)。

技术管理员打开或刷新「订阅与席位」时，距到期不超过 30 天的有效订阅会显示续费提醒。服务端以同次账务读取的时间计算，按 24 小时向上取整。剩余不足或恰好 24 小时显示「24 小时内」。到期后提示业务新增和修改已暂停，历史资料仍按原授权查阅或导出。受管版继续显示在线续费尚未开通，提醒只在这个账务页出现。

在合成订单区，先选择账务团队和订单类型，再粘贴完整订单号并按回车或点击「查询订单」。结果单独显示，原列表保留当前页。找不到时，请核对团队、订单类型和订单号。单笔查询仅显示已保存的订单状态。需要向合成收款来源核对时，另行执行订单列表中的核对操作。

订单显示待收款、已核验收款待处理或已兑现。每次查单或核对均需当前设备证明和账务权限。核对通过已配置的可信合成来源完成，客户端没有收款确认入口。只有服务端兑现事务成功，订单才显示已兑现，期限和容量才相应生效。已核验待处理的年单可在释放承诺后核对原订单。

订单列表中的「恢复兑现」用于已有验款记录、尚未兑现且无已知关单或退款异常的模拟订单。网关不可用时也可尝试，所用收款事实来自服务端账本。权限和订单归属在兑现事务开始和提交前重新核对。若原单仍须复核，保留原验款事实，按订单状态提示处理。重复操作返回原回执。

支持恢复兑现的合成服务会在收到带 `X-Shenyi-Billing-Recovery: recorded-payment-v1` 的账务概览请求时返回 `canResumeFulfilment: true`。恢复通过既有核对订单 IPC 指定已保存收款来源。主进程仅在独立的 `resume-fulfilment` 路由发送空 JSON。查单核对仍可独立查询可信网关。

官网合成下单开启后，新年费和增购订单仍由官网创建。桌面技术管理员可对本团队原单执行已配置的单笔或批量对账，并可使用库内已验款记录恢复兑现。单笔和批量核对需要可信合成查单来源，批量能力还须显式启用。官网一键演练的默认订单继续保持待收款，默认配置无模拟查单来源。完成核对或兑现后，可在官网只读查看同一订单的状态。团队 API 的模拟通知路径在此模式保持关闭。

`GET /api/auth/billing/access` 返回当前设备会话可操作的账务团队。`GET /api/teams/:teamId/billing/overview` 在一次读取中返回该团队的期限、席位和可用方案。带 `X-Shenyi-Billing-View: expiry-reminder-v1` 的账务概览请求在符合条件时会额外返回 `subscription.renewalReminderDays` 整数，范围为 1–30。服务端保持旧请求的响应字段，客户端也接受未返回该字段的旧服务。单笔查阅使用 `GET /api/teams/:teamId/billing/orders/:orderId` 或 `GET /api/teams/:teamId/billing/seat-orders/:orderId`。IPC 限定为查权限、查概览、列订单、查单笔、建单和核对订单，主进程校验参数及业务响应。受管服务提供只读概览，模拟订单操作由现有配置与授权单独控制。

Windows 原生验收使用独立的 Electron 配置、合成账号和新建 SQLite，运行 `node desktop/billing-orders-smoke.cjs`。合成金额仅供流程测试。正式下单和付款集中在官网。正式价格、商户接入、真实支付和退款及 macOS 原生验收仍待交付。 [官网下单演练](../website/README.md#官网下单演练)
