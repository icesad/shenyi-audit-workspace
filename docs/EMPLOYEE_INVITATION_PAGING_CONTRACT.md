# 员工邀请历史分页合同

本项接续M4，分支`codex/employee-invitation-pagination`，起点`ad421a03f45b013033f8a3b579a1145335b8c3eb`。原来仅展示最近50条；本项增加历史可达性，不增加邀请权限、受邀职级、自动发送消息或正式SMS服务。

## 服务端

`GET /api/teams/:teamId/employee-invitations`接受可选`after`与`limit`。每页默认50，`limit`为规范十进制整数1至50。未知、重复、空或畸形参数拒绝；其他邀请及激活路由、非GET列表仍拒绝查询参数。

返回`{invitations:[...],nextCursor:null|string}`。每条仍只有`invitationId,teamId,role,phoneMasked,expiresAt,status`；不新增总数、明文手机号、邀请码或独立来源/创建时间字段。`nextCursor:null`表示本次读取时已无后页，列表读取不写业务数据。

business与operator两来源按`created_at DESC, invitation_id COLLATE BINARY DESC, source.name DESC`归并。每来源最多取`limit+1`再归并截页；seek条件与比较器使用同一三键，包含跨来源同一时间/同ID的平局。重复ID不擅自合并，已有撤销歧义拒绝保持。

游标为最多1024字符的规范base64url JSON元组`[1,userId,teamId,source,createdAt,invitationId]`。服务端核对规范编码、精确结构、类型、ID、来源和非负安全整数时间，绑定当前账号与团队，并验证锚点在指定来源中仍精确存在。游标可逆，不是加密、签名或权限凭证；包含的定位元数据不应作为业务内容展示。合法用户可以选择本团队内存在的定位点，不因此获得额外读取权限。

每页仍执行原有认证、设备与有效会话门以及当前`canInvite`；读取后再核对当前账号和权限。复制游标、跨团队、跨账号、撤权、成员/团队停用都不能绕过这些门。邀请已接受、撤销、过期的状态仍按当前数据返回；不把状态变化当成自动删除锚点。

新邀请写入首页，不随正在浏览的历史页插入；刷新返回首页可查看新记录。前页按钮重新读取相应位置，不承诺跨多次请求的一致数据库快照或不变的页码。锚点失效时清空当前列表，重新打开/刷新从首页开始。

## 桌面客户端与界面

沿用`listEmployeeInvitations`和`invitation-list`，仅增加`after/limit`输入白名单，不增加IPC接口。主进程校验游标格式及长度、数量、团队、掩码、职级、状态及响应形状；拒绝空页继续游标、原位置循环和超过请求数量的列表。旧服务仅允许默认无`after/limit`调用缺少`nextCursor`并归一为null；显式分页必须返回该字段。

界面保留当前一页及不展示的定位栈，提供上一页/下一页，无团队总数。加载中禁止重复导航和写入。创建成功回首页并保留本次一次性邀请码；普通刷新/翻页/关闭/切换账号团队/失权/离线清理列表或邀请码，不把迟到响应填回已离开的上下文。关闭后重新展开须重新核验权限并读取首页。

撤销使用当前行的原邀请ID，只发一次POST；随后刷新当前页。响应未知不自动重发，用户可重新读取当前状态。创建邀请码仍不代表已发送消息、激活员工、授予项目权或计费席位。
