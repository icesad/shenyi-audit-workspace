# 审易首版脱敏与上传方案

**2026-11-22 · 待产品负责人和米老师确认**

首版面向国央企审计项目，建议采用 **本地保管原件、本地验算、按批次批准共享**。研发和演示使用合成数据。真实资料先确定级别、用途、处理环境和接收范围，再由指定人员在获准的本机制作副本。审易团队版当前只查阅负责人验密并显式导入的已保存账表快照。首试点拟开放的脱敏 Excel 上传、字段预检和批次审批，需要在启用前验收。 [团队账表首版决定](LEDGER_CHECK_ACCESS_DECISION.md)

## 首版实现取舍

- **本地规则是主流程。** 在客户批准的终端离线读取 Excel 工作副本，由项目字段白名单决定删列、分配稳定代号和保留验算值。按项目版本维护映射，输出从空白工作簿重建。用确定性规则检查表头、类型、前导零、重复键、未匹配、前后行数和金额合计，并复核最终文件的隐藏内容和结构。
- **AI 只辅助查漏。** 如项目批准使用本地 AI，可在同一受控环境辅助标出摘要、备注等自由文本中的可疑内容，只返回待核位置和风险类型。经办人在本地复核这些提示，再按确定性规则重建副本。数值、日期、代号映射和审批结论由规则和授权人员控制。真实原件、映射表、提示内容和运行日志均在批准的环境处理。接入本地模型前，应核对模型和插件的联网、遥测及云同步设置，保留可中止的人工复核流程。AI 是可选步骤，整条规则流程可以离线独立运行。
- **先部署本地脱敏工具。** 首试点拟只共享经批准的最小副本。若客户要求团队协作也在指定内网运行，再按项目条件评估整套私有部署。真实资料入口和审批在正式启用前验收。

先用合成样例验证操作，并记录可复现的通过和拒绝结果。 [实习生本地试跑教程](LOCAL_EXCEL_DESENSITIZATION_TEST_GUIDE.md)

## 1. 开工前确认项目范围

| 情况 | 首版处理建议 |
| --- | --- |
| 研发、演示或培训 | 使用合成 Excel，保留表结构、勾稽关系和异常案例。 |
| 真实资料需验算，项目已批准本地处理 | 在客户或事务所书面认可的设备和目录工作，按任务提取最少字段。原件、映射表和完整底稿留在指定环境。 |
| 拟上传到审易团队环境 | 只放行书面批准的数据范围、目的、接收人员和保存期限内的最小副本。首试点范围建议限于批准的结构化表格及对应快照。 |
| 涉及国家秘密、级别存疑，或涉及核心、重要数据 | 暂停常规导入和上传，交客户保密或数据安全管理部门和事务所按适用规定确认级别及专用处理路径。 |

项目开工时，由客户授权的数据负责人和事务所按业务约定书或确认函核定资料范围、分类分级、允许处理和存放的位置、接收团队或项目，以及退出后的返还、删除或归档安排。涉及委托处理个人信息或重要数据时，按实际分工落实适用的合同、事前评估和安全要求。可凭映射表恢复自然人身份的副本继续按适用的个人信息要求管理。 [事务所数据安全办法第七至十三条](https://www.cac.gov.cn/2024-05/10/c_1717011564369521.htm) · [个人信息保护法第二十一、五十五及七十三条](https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_515a4b20c12f430eab54bb4f56d89f56.html) · [网络数据安全管理条例第十二、三十一条](https://xzfg.moj.gov.cn/front/law/detail?LawID=1734) · [保守国家秘密法第三十、三十一条](https://gdca.miit.gov.cn/zwgk/zcwj/flfg/art/2024/art_4870c40a6f8249389684d03786d41639.html)

## 2. Excel 字段处理表

| 处理方式 | Excel 字段 | 放行时怎么判断 |
| --- | --- | --- |
| 删除 | 与本次验算无关的自然人姓名、身份证号、手机号、地址、银行卡号、账号原值、工资明细。 | 确有审计用途的受限数据由获准人员在指定环境回查。交付副本只保留本程序批准的最小字段。 |
| 删除 | 无需关联的统一社会信用代码、发票号、合同号、开户行和账号、无关备注、签名扫描件或嵌入附件。 | 从新文件中省去这些列和值。文件名、表名、隐藏内容、外链和缓存一并检查。 |
| 换代号 | 企业或被审计主体名称、跨表匹配所需的客户、供应商、部门或项目。 | 同一项目内同一对象用同一代号，不同对象用不同代号。无匹配用途的字段直接删。 |
| 换代号 | 凭证号，以及确需跨表匹配的合同、发票等业务键。 | 使用项目内唯一且可回查的代号。按账套、期间或字别和原号确定来源，凭证内分录行号保持原值。映射表单独加密存放。 |
| 保留验算 | 项目与主体代号、期间起止、币种、金额单位及精度。 | 三张表同主体、同账期、同口径。代码列使用文本，保留前导零。 |
| 保留验算 | 末级科目编码、凭证代号、分录行号、获准的日级日期、借方及贷方金额。 | 保持原日期、原精度、原借贷列和红冲符号。跨期、缺失关联和重复行应能被发现。 |
| 保留验算 | 余额表的期初、本期及期末借贷各列，报表行标识、期初期末金额、科目映射及正负方向。 | 核对行范围、发生额、余额滚动及报表等式。只提供部分数据时写明范围。 |

**金额、日期和关联关系也可能受到外发限制。** 按项目授权保留准确值。若不允许外发，在获准环境完成验算，仅共享批准的结果。对实质性测试有影响的字段，由米老师或授权复核人确认。涉及科目编码置换时，先证明跨表一致、映射一一对应且层级处理正确，再使用已确认的手工映射。

## 3. Excel 本地脱敏操作

1. **登记并保管原件。** 在授权设备用 Excel 桌面版操作，选择单位批准且未纳入个人网盘同步的目录。将收到的文件按项目只读保存。记录接收时间、来源批次、文件摘要和可回查位置。复制一份到受控工作区，保持原有计算逻辑和公式。打开工作副本时按单位策略禁用宏和外部链接更新。
2. **按白名单选列。** 先在原环境明确主体、期间、表和行范围。验算用不到的姓名、身份证号、私人手机号、地址、银行账号、统一社会信用代码、发票或合同编号、自由文本备注等列，从交付副本移除。检查摘要、标题和单元格正文是否夹带真实姓名、对方账号或项目备注。业务确需某类识别字段时，优先用项目内代号，具体字段由业务复核人和客户授权范围决定。真实金额、特定日期、科目名称也可能敏感，由项目分级决定是否能对外共享。
3. **为需要跨表关联的值分配代号。** 在项目内使用一张独立映射表。对同一主体、客商或凭证使用同一代号，不同对象使用不同代号。凭证原号跨账套或月份重复时，用账套、必要期间或字别与原号组成稳定键，再分配本批核验范围唯一的凭证代号。复用同一项目映射版本，变更时保留版本记录。新项目重新分配。避免以身份证后四位等原值片段作为唯一代号。
4. **核对类型并冻结工作结果。** 如从 CSV 导入，在“数据 → 从文本/CSV”中先把科目编码、凭证号和其他 ID 列设为文本，避免前导零丢失或长编码变形。金额列保持数值及批准的精度，日期保持原日期和粒度，交付时可统一显示为 `YYYY-MM-DD`。已经失真的编码从可信源重新取数。工作副本内可用精确匹配查代号，逐项解决未匹配、重复键和类型冲突。对有公式的源表先确认缓存是否可信。需重算时由原环境的业务人员在获准条件下执行并留记录。 [Excel 保留前导零及长编码](https://support.microsoft.com/zh-cn/excel/keeping-leading-zeros-and-large-numbers) · [Excel XLOOKUP](https://support.microsoft.com/zh-cn/excel/functions/xlookup-function)
5. **新建交付工作簿。** 打开空白 `.xlsx`，预设列格式，仅把获准区域用“选择性粘贴 → 值”写进去，再补必要表头和数值格式。按批准的行范围导出，先核对隐藏行、筛选和合计行是否会影响完整性。采用项目代号命名文件和工作表，例如 `P-012_序时账_2026-01_v01.xlsx`。整表拷贝、另存原工作簿、仅隐藏列或给单元格加黑底，都无法满足本方案的放行检查。
6. **检查最终文件。** 保存、关闭后重新打开，从交付文件本身复核。支持文档检查器的 Excel 桌面版可用“文件 → 信息 → 检查问题 → 检查文档”。同时用受控环境的包检查工具检查 `.xlsx` 内部组成。检查隐藏表和行列、批注、作者与文件属性、定义名称、公式和外链、超链接、查询和数据模型、透视缓存、图片、嵌入附件及宏。检查器有盲区。缺少检查能力、发现无法解释的内容或残留原值时，将文件退回重建，或交有相应检查能力的授权终端复核。 [Microsoft 工作簿隐藏数据检查](https://support.microsoft.com/zh-cn/office/collab-files/remove-hidden-data-and-personal-information-by-inspecting-documents-presentations-or-workbooks)
7. **登记拟上传版本。** 对最终文件计算 SHA-256，由复核人和放行人针对同一摘要签核。上传前重新比对摘要，上传后核对回执或下载复核的摘要。改过文件内容就重新检查和审核。

临时表中可使用以下公式分配代号。示例中 `A2` 是已由项目核实的原始匹配键，`映射` 工作表的 A 列为原始键、B 列为代号。映射表每个键仅保留一条，所有“未匹配”项逐项复核。此公式和映射工作表均只在本地工作区使用。

```excel
=XLOOKUP(A2,映射!$A$2:$A$1000,映射!$B$2:$B$1000,"未匹配",0)
```

## 4. 真实验算必须保留的字段

下面是审易现有手工账表映射的最小输入。每次以同一项目、同一主体代号及同一期间为准。批次单统一登记期间起止、币种、金额单位及小数精度。现有手工入口支持明确设置 0 至 6 位小数，按输入的单位核对。 [手工账表映射源码](../dist/audit-preparation.js) · [自动识别源码](../dist/audit-auto-check.js)

| 数据 | 必须保留 | 复核要求 |
| --- | --- | --- |
| 序时账／凭证明细 | 末级科目编码、验算范围唯一的凭证号或代号、凭证内分录行号、记账或本程序采用的对应日期、借方发生额、贷方发生额。 | 同一凭证各行仍属于同一张凭证，凭证与分录复合键无重复。保留跨表关联、期间边界、负数及红字方向。需要做截止性检查时保留相应日级日期，并记录抽查窗口。 |
| 科目余额表 | 与序时账一致的末级科目编码、期初借方及贷方余额、本期借方及贷方发生额、期末借方及贷方余额。 | 按末级科目核对各列合计及余额滚动。父级、总计及明细在选取范围内避免重复计入。 |
| 资产负债表等获准余额类报表 | 稳定的报表行标识、期初金额、期末金额。另保留经米老师或授权业务复核人核定的报表行到科目的对应关系、每项正负号和资产、负债及权益核对所用行。 | 所有代码按同一版本映射。总计行与其组成明细按程序选择，避免双计。需要利润表或现金流量表时另定发生额口径及范围。 |
| 来源与范围 | 脱敏工作簿的代号、数据范围、导出版本、工作表与行号定位、文件摘要，必要的来源引用。 | 原表名、原行和原凭证的回查关系在受控环境保管。若保存新的团队账表快照，应按新副本重建来源引用和摘要，审查快照里的输入、映射、引用及结果。 |

真实验算保留原金额和已批准的精度，区分负数、零和空白。不明数据先回查。只授权部分科目、抽样或一个月时，副本和结果注明过滤条件及覆盖范围，完整性结论限于获准范围。如果日期或金额禁止外送，应在原环境验算，按批准范围共享结果。送审前对照原范围复核行数、凭证数、唯一键、缺失关联、借贷合计、期末净额滚动及报表差异。抽取一笔普通分录以及实际存在的期末边界、冲销或其他异常样本，确认能由脱敏行回查到原件。 [审计证据准则第1301号](https://www.cicpa.org.cn/ztzl1/Professional_standards/xxzztx/zyzz/sjzz/202105/P020240412542695263912.pdf)

原表头、科目层级或编码前缀改变时，先复核自动识别结果。首试点建议优先采用已核对的手工列映射。真实身份映射表独立留存，报表与科目的业务映射按验算和授权需要纳入副本。

## 5. 原件、映射表与副本放在哪里

| 文件 | 放置和访问 |
| --- | --- |
| 原始 Excel、支持性原件、含公式的原工作簿 | 留在客户或事务所书面批准的受控项目资料库，按项目只读保管。获授权的项目人员按审计需要回查。保留年限按审计归档及客户约定执行。 |
| 真实身份到代号的映射表、原件定位清单 | 独立存放在同一批准环境下的加密受限目录，权限与交付目录分开。由指定保管人维护，只有获明确回查授权的人可读。映射表采用项目内版本，备份和回查操作按同级要求留痕。 |
| 脱敏制作副本、中间导出 | 留在本机受控工作区，按项目约定在确认后清理。 |
| 拟上传的脱敏副本、对应快照和批次审批记录 | 放入项目待审目录。通过全部审核后，仅批准对象进入指定审易团队和项目。审批记录填写项目代号、文件摘要、人员和时刻，避免把真实名称、原文件路径或原值抄到上传记录里。 |

原件与映射表均留在受控环境。合同、扫描件和完整底稿 ZIP 在首试点走原件保管规则。现有完整底稿功能会携带 ZIP 原件和已有冻结快照，首试点按单独的授权和验收处理该功能。 [完整底稿包与权限决定](WORKPAPER_ACCESS_DECISION.md)

## 6. 谁审核后才能上传

| 顺序 | 人员 | 必查事项 |
| --- | --- | --- |
| 1. 确认项目授权 | 客户授权的数据负责人及事务所指定责任人 | 书面确认级别、允许字段、用途、拟上传的系统／团队、人员和期限。范围改变时重新确认。 |
| 2. 制作并登记 | 获授权的资料经办人 | 本地脱敏，生成获准副本，登记来源批次、字段、摘要和自查证据。 |
| 3. 业务复核 | 米老师或项目授权的业务复核人 | 核对第 4 节的字段和勾稽结果，确认数据范围、差异、可追溯性及该副本能支持的程序。 |
| 4. 数据安全复核 | 项目授权的数据安全复核人 | 确认可上传范围、文件内外残留、隐藏内容、目标环境与接收对象、摘要和保管安排。经办人与放行人分开。 |
| 5. 放行并上传 | 项目负责人批准，指定上传人操作 | 两项复核通过后签核该文件摘要。上传人核验权限和项目，上传匹配版本并登记回执。技术管理员按授权设置账号和目标权限。 |

信息不全、任一复核未通过、目标改变或摘要不一致时，该批次退回经办人。重新生成文件后使用新摘要重审。可用以下字段填写一条批次回执，空项在放行前补全。

```text
项目代号／批次号
客户授权文件编号和允许的用途、字段及期间
目标环境、团队／项目、接收人员范围和保留期限
脱敏文件名、版本、SHA-256
行数、凭证数、借贷合计、异常和抽样回查记录的位置
经办人、业务复核人、数据安全复核人、项目负责人及各自确认时间
上传人、上传时间、文件摘要核验结果及回执编号
```

Windows PowerShell 可用 `Get-FileHash -LiteralPath 'P-012_序时账_2026-01_v01.xlsx' -Algorithm SHA256`，macOS 可用 `shasum -a 256 'P-012_序时账_2026-01_v01.xlsx'`。在最终文件所在的受控目录运行。

## 双方待确认

- **米老师**确认 Excel 字段白名单、默认手工映射范围、账表勾稽容差及需要在原环境复核的证据。
- **产品负责人**确认首试点允许上传的文件类型和模块、批次审批记录方式、上传角色、遇到残留时的退回机制，以及由谁担任数据安全复核人。
- **双方**确认第 2 节字段表和规则放行条件。实习生可按合成三表教程先跑，提交本地回执。实际客户资料按第 1 节取得项目级确认后再安排验收。 [本地试跑教程](LOCAL_EXCEL_DESENSITIZATION_TEST_GUIDE.md)
