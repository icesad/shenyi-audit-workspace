# 旧正式项目归属登记

用户已确认由产品负责人审核目标团队和首位项目负责人。此功能只登记团队治理关系，保留旧 UUID、固定业务编号及来源，不搬客户原件、底稿、清单、合同或报价库。真实客户来源上云仍需相应授权。

## 使用路径

1. 在旧版“项目登记表”完成本行保存及风险等级、项目类型、固定编号核对，点击“导出团队归属审核来源”。来源只读导出；缺记录、编号或最新中标资格时拒绝，不自动补造。
2. 产品负责人在团队桌面中打开“旧正式项目归属审核”，选择该 JSON。先核对 UUID、原业务编号、历史经理文本及三类中标时点；历史姓名不映射成账号。
3. 选择目标团队和有效的经理／合伙人账号作为首位团队负责人。技术管理员兼任业务职级时，仍需事先独立批准。
4. 分别选择初始读取、管理、核对权限，明确确认并输入当前审核账号密码。项目所有权本身不自动包含这些资料权限。
5. 审核查询编号在提交前已显示。成功返回登记回执；遇到未知结果，使用原编号只读查询，不能根据暂时404断言最终未提交，软件不会自动重发。
6. 首位负责人按批准权限从既有项目面板继续管理采集工作。原本机资料和锁定状态保持原样；不能把此登记称为完成专业资料迁入或审计签发。

取消、清除来源、退出或设备状态变化会使主进程私有来源失效。已发送的审批不能靠关闭面板撤回；公开查询编号可以保留，由同一审核人重新登录核对。来源原路径和 JSON 正文不进入 renderer。
