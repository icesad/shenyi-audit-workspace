# M5 本地账务候选

Windows 可双击 [Start-Team-Billing-Candidate.cmd](../Start-Team-Billing-Candidate.cmd)。启动后用独立的 SQLite、桌面配置和设备目录，服务监听随机本机端口。关闭窗口后，数据库和预置订单清单可供核查。再次启动会创建新的演示环境。

## 操作路线

三个合成账号的密码均为 `ShenyiDemo!2026`。首次登录后按屏幕提示绑定电脑。

| 账号 | 可操作范围 |
| --- | --- |
| `billing-admin-demo` | 在「订阅与席位」查询、核对订单及恢复兑现 |
| `refund-owner-demo` | 在「退款受理」输入已核验原单，登记受理和跟进 |
| `intern-a` | 查看已分配采集任务，验证账务及退款入口均无权限 |

启动控制台会给出 `billing-demo-cases.json` 的位置，五个预置订单号每次启动重新生成。团队技术管理员可先走以下流程。

1. 先在增购列表核对 `seatAddition`。报价期限内的模拟收款会按原订单给本期增加两个席位。
2. 再在年费列表核对 `annualRenewal`。续订使用该订单锁定的下期席位数。
3. 单独核对 `timedOutAnnual`，先看超时关闭，再核对一次，看迟到收款待复核。该单暂缓发放权益。
4. 核对增购 `refundSeat` 后退出。以退款负责人登录，用同一订单号查看并登记受理，再记录一个跟进事项。已经核验的收款与既有席位继续保留。

「恢复兑现」可以在上述流程之前单独走查。先打开「增购席位」，记下已购席位数，在订单列表找到 `recordedPaymentSeat` 的订单号。订单应显示已核验收款待处理。点击该行的「恢复兑现」后，订单变为已兑现，已购席位增加 1 个，本期到期日和原收款确认时间保持一致。若先做普通「核对订单状态」，合成查单来源对这笔订单无新回执，状态和席位保持原值。单笔查询用于比对订单号和状态，恢复操作位于列表。

可以先在桌面选择「团队年费」或「增购席位」，把合成清单中的 `orderId` 填入订单号查询。单笔结果应与原订单一致，仍可继续在原列表核对。切换订单类型或退出账号后，清除单笔结果。

预置发生的账务事件由内存中的模拟网关返回签名回执。届时已过期的预置待付订单会按原截止时间处理。新建的普通演示订单可以检查建单结果，预置外的订单不会返回模拟收款。此入口也可由 Node 24.15 以上的 24.x 执行 `node scripts/team-isolated-preview.mjs --billing-demo`；macOS 原生使用待验。

## 验收范围

当前合成候选对应服务端期限和席位账本、到期读写分界、主动续订及增购、异常回执、批量核对、负责人受理和超时关单。证据应分别核对桌面操作、服务授权、实际数据库和重复回执。旧桌面入口、共享库及原有客户资料流程另按原验收范围执行。

正式价格、服务合同、生产商户及退款、最终权益处置、主动到期通知、macOS 安装更新和国内上线，各有独立验收条件。

## 官网续费和恢复业务走查

同一个已到期合成团队中，技术管理员从桌面打开受信官网，选择下一年度席位并明确建单。官网回执和桌面单笔查询使用同一订单号、金额和席位。待支付时到期日期及权益保持原样，经理仍能查阅历史资料。

隔离验收使用独立的本机模拟收款入口与官网共用一个合成账库。官网仍拒收模拟回调。可信模拟来源对原订单确认收款后，从首次确认时刻起计算一个北京时间自然年。重复递交同一回执仍只兑现这份期限和原锁定席位。技术管理员从桌面刷新账务和查询原单，可见同号已到账。经理使用原会话和采集授权，重新打开原件并新建一项任务。

这项验收使用外置驱动提供模拟收款。面向评审人员的官网一键入口继续提供合成下单，到账结果由本轮驱动触发并在桌面查验。生产商户和对账退款须各自验收。
