# 单项目资料保全与本机恢复

2026-11-16，M4D 本地候选，分支 `codex/material-project-preservation`。本功能在旧版网页的“审计程序 → 资料收集与核对”中使用；完整边界见[执行合同](MATERIAL_PRESERVATION_CONTRACT.md)。团队客户端的项目登记、权限和资料迁入继续另行推进。

本机旧端入口为 `http://127.0.0.1:8773/`；服务未运行时，在本仓库使用 Node 24.15 以上的 24.x 执行 `npm run dev`。浏览器资料按地址与浏览器资料区隔离，导出须进入原来保存资料的位置。现有 `Start-Team-Review-Preview.cmd` 是团队桌面预览入口，当前不承载本片旧资料恢复功能。

## 保存什么

“导出资料保全包”保存一个项目的完整资料清单、操作历史，以及历史中每次“上传资料”引用的所有原件。已经移除的附件和替换清单前的旧版本原件也包含在内。项目 UUID、修订号、标题版本、原件 ID、原件字节和原有关闭状态保持。

旧“导出清单与核对记录 JSON”仍可使用，但其中没有原件正文；旧归档 ZIP 也不能替代此保全包，因为它不包含全部已移除和旧版本原件。

这份包只覆盖该资料模块，不是整个项目或整个软件的备份。不含未保存的原始 Word 清单文档、底稿原包、报价、合同、发票、成本、其他数据库或未被资料历史引用的文件。历史中手工填写的核对人、核对通过和关门记录会原样保存，不能当作当前员工的身份认证、专业签审或审计完成证明。

## 导出

1. 在原浏览器、原地址的旧版资料模块，选择已有正式项目，或进入已有独立试用资料区。
2. 点击“导出资料保全包”，等待全部历史原件完成读取与完整性核验，再保存下载的 ZIP。
3. 妥善保管原件与保全包。包未加密，SHA-256 用于检查完整性，不证明提供者身份，也不替代备份介质保护。

如果历史引用缺少原件、原件损坏、存在未关联文件、导出中源记录改变或超出容量限制，导出会明确失败，不生成省略部分资料的“成功”包，也不会更改原资料。

## 预检与恢复

1. 先准备同一个项目 UUID 的空资料区。正式项目必须已经通过原有立项流程存在于目标本机；本功能不会从 ZIP 新建立项或补造编号。UUID 相同还必须匹配正式／试用范围。
2. 点击“恢复资料保全包”，选择原样保存的 ZIP。预检显示项目、UUID、资料区、版本、关门状态、当前与历史原件数量、总字节及包 SHA-256。预检和取消不写资料记录或原件；打开目标可能初始化空的 IndexedDB 结构。
3. 正式包手动选择对应已有项目。试用包可明确选择“恢复到独立试用空资料区”；此动作不会自动创建试用模板，取消也不创建模板。日常“独立试用”入口仍沿用原有模板创建行为。
4. 核对摘要与历史身份说明，勾选确认并在确认对话框中继续。恢复前会重新检查原包与已确认摘要、当前项目、目标空态和文件 ID 冲突。
5. 成功后核对清单和操作留痕，可从历史中下载已移除和旧版本原件。若提示“已恢复，但刷新失败”，先刷新核对，勿把它当作事务未提交而反复恢复。

目标只要已有任何清单记录、该项目的孤立原件或任何项目占用相同原件 ID，都会拒绝恢复，不覆盖、不合并。所有记录与原件在一个事务中写入；写入故障或并发冲突会全部撤销，不留下半份资料。关门记录恢复后仍关门，后续修改须走原有说明理由并重新开门流程。

恢复还会逐份复用原上传的内容准入校验，包括文件真实格式、文本编码及原有 Office 宏／加密限制。完整性预检通过仍可能因原件不符合准入而拒绝；此时保留原包与源资料，不静默改名、净化或改写原件。该检查不等于完整恶意软件扫描。

本轮没有跨团队迁入、云同步或账号授权转换。旧项目所属团队与首位项目负责人须按后续明确审核流程建立，不能根据旧表格中自由填写的经理姓名推断账号。

## 格式与容量

标准 ZIP32，成员仅为 `manifest.json`、`record.json` 和 `originals/<原件UUID>.bin`，不执行包内正文。校验清单历史、范围、ZIP 边界、CRC32、原件大小和 SHA-256；拒绝缺件、重复成员、额外成员、路径穿越、加密、ZIP64、压缩成员和尾随数据。仅接受本功能产生的格式，普通归档 ZIP 不能直接恢复。

每份原件 1 字节至 12 MiB，全部历史原件最多 150 MiB／5000 份；清单 JSON 最多 24 MiB，manifest 最多 4 MiB，整个包最多 180 MiB。超限明确拒绝，不截断或重写 Office 文件。当前浏览器的存储配额仍可能小于这些上限，配额不足时事务会取消。
