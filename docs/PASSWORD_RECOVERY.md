# 找回密码：本人验证与独立授权

日期：2026-11-15；M2本机隔离候选。登录页已接短信挑战、独立恢复凭据及新密码确认；真实SMS和恢复审核签发链尚未开通，默认禁用。它与登录后的[本人改密](PERSONAL_PASSWORD_CHANGE.md)是不同流程。

## 已确认与尚未实现

用户本轮已确认：员工忘记密码，由团队管理员审核短信之外的恢复授权；团队管理员本人由产品负责人（当前用户）审核。两种情况都仍需本人手机号验证码。不能由员工自己批准，不能将邀请授权或普通审计职级当成恢复审批权。

当前已实现的是桌面恢复入口和既有可信 `recovery.authorize` 适配器边界。下一步必须实现相应审批记录、当前密码重验、一次性授权签发/撤销及当前审批权复查，才可启用正式流程；当前没有“谁都可生成凭据”的接口，也未自动为任何账号增加恢复审批权。真实短信、审核人的身份建立和生产配置仍需各自具备。

## 当前操作

1. 退出账号，在登录页展开“找回密码”。能力状态必须明确确认可用，且桌面具备两个窄接口，才能请求验证码。
2. 使用已验证绑定手机号获取 `reset` 用途的短信验证码。响应不说明账号是否存在；未知手机号不能创建或恢复用户。
3. 输入短信验证码、经独立授权流程取得的恢复凭据、新密码及确认密码。验证码单独不能重设；恢复凭据不是短信验证码、旧密码或团队邀请票。
4. 服务端明确批准并成功保存后，原子更新密码及版本、撤销该用户全部旧会话和手机号挑战。保留手机号、内部身份、团队角色及资料权限；不自动登录。
5. 使用新手机号密码登录。超时或响应不明时提示结果可能已经完成，需登录核对；不自动重复写入，不声称取消输入就撤回了请求。

新密码沿用12至128个Unicode字符、最多512 UTF-8字节的规则，大小写、前后空格和Unicode序列不暗改。两次新密码不一致不会发出重置请求。恢复凭据按原始字符串提交，不在本地持久化、日志或结果中回传。

## 服务端修复与可信边界

原实现只判断当前手机号仍指向原用户，没有绑定发码时的手机号版本和验证时间。独立真实SQL测试复现8处边界：同值重新绑定、验证时间变化，以及授权/密码计算期间出现这些变化，旧验证码仍可能成功。此问题不代表已发生真实账号事件；本任务仅使用合成库复现。

新增 `recovery-schema.sql` 的 `team_phone_challenge_bindings` 单表，记录已知有效手机号发码时的 revision 与 verified_at，和挑战创建同事务。恢复HMAC同时认证这两个字段，校验时重新读取；SMS发送返回、外部授权完成、密码计算后事务内都核对当前归属。元数据被同步篡改也不能让旧验证码匹配。

手机号验证时间必须为有效正整数且不晚于服务端当前时刻。无效或未知映射仍走不暴露存在状态的发码响应，但不能恢复账号；正常未知手机号响应中没有 owner/existence 信息。`bind` 原HMAC和首绑行为保持。旧库中无快照的未用 `reset` 挑战拒绝，用户重新发码；不改写旧挑战或自动复活它。旧 `bind` 票仍按原合同验证。

恢复仍要求服务端注入的 authorizer 对 `userId/challengeId/recoveryProof` 明确返回 `true`。生产适配器必须独立验证目标、挑战、批准者当前权限、期限、单次消费与撤销，不能把“非空凭据”或客户端 `approved:true` 当批准。当前真实供应商和正式签发链缺席，能力保持 false。测试 authorizer 明确为合成、按用户＋挑战＋期限匹配并单次消费，不是生产审批服务。

验证次数在异步工作前扣除，失败不退还；挑战有效期5分钟、单次使用，SMS全局与手机号限流沿用既有规则。账号停用、手机号/密码版本变化、用途错误、过期、重放、跨账号挑战均拒绝。外部批准可能已被消费后才发生数据库失败，需要重新核对授权；不会为重试放宽校验。

## 桌面边界

新增 `requestPasswordRecovery({phone})` 和 `recoverPassword({challengeId,code,newPassword,recoveryProof})`，分别固定调用 `/api/auth/phone/challenges`（purpose固定reset）和 `/api/auth/phone/reset`。只在未登录状态使用，不附Bearer；不允许传userId/role/approved/服务器路径。响应仅保留挑战ID/期限或 `signedOut:true`，不采纳上游多余身份或令牌。

总39项窄IPC、9个form、14处密码输入（恢复凭据为密码类型）。能力缺席如实禁用。关闭/换手机号/登录方式/账号变化/unload清挑战及秘密；验证码发送和重置都跨面板关闭保持单次请求锁。迟到响应不得清退新账号、恢复旧挑战或把新页面永久锁住。原生details的延迟toggle不清除刚输入的值。
