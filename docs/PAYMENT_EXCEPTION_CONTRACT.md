# 模拟退款与拒付的复核记录

M5I 接收模拟网关已经确认的全额退款或拒付。记录单独保存原订单、原收款交易、事件编号、金额、发生时刻及验真内容。本团队技术管理员在原订单查询中看到异常类型、发生时刻和待复核状态。订单原有收款与兑现状态仍可核对，界面不显示网关交易标识或签名。

已发放的期限、席位和成员访问状态继续由原账本管理。异常证据先于权益兑现写入时，匹配的后到收款仍留存用于对账，该订单暂不发放新权益。较早年单的全额异常经确证后，其他正常年单可以按原顺序继续，其他待兑现收款仍遵循现有补偿顺序。首版退款由产品负责人受理，团队暂不在客户端提交退款申请。负责人已可按[受理合同](BILLING_REFUND_INTAKE_CONTRACT.md)登记。退款与拒付的最终权益处置、部分退款和真实商户操作另待确认。

## 接收与核对

合成账务配置显式启用 `paymentExceptions: true` 时，`POST /api/billing/simulation/payment-exceptions` 接收可信网关通知。已绑定设备的本团队技术管理员可通过既有订单核对入口触发配置好的查单来源，来源以 `{kind:'payment-exception',body,signature}` 返回异常。查单须匹配当前订单和产品，服务端在同一事务中复验当前设备、账号和团队权限并记录。关闭接收后，先前已有的异常证据继续参加查询与权益检查。

回执为规范 JSON，字段顺序是 `protocol,merchantId,eventId,originalTransactionId,orderId,product,amountMinor,currency,kind,occurredAt`。协议为 `shenyi-simulation-payment-exception-v1`，类型为 `refund` 或 `chargeback`。消息上限 16 KiB。签名使用独立的 HMAC 消息域 `shenyi.billing.simulation.exception.v1\0` 和现有合成网关服务端密钥。金额须等于原订单锁定的人民币分整数。发生时刻须位于原下单和异常首次入账之间。已有收款时，还须关联同一交易并晚于或等于该收款时刻。

同一规范事件可以重放，仍只有一条持久记录。每张订单和原交易最多绑定一条全额异常。跨产品交易或事件复用、金额或时间矛盾、变更后的重放均留待人工核对，不覆盖原事实。有效异常先持久化；已经核验但未兑现的匹配收款可以补记，设备或客户端提交不能授权退款。真实支付、退款申请、部分退款、争议结果更新和生产验收不在本候选运行范围。
