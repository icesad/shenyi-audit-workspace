# M2：本人密码修改

日期：2026-11-15；`codex/personal-password-change`从`911b53a`接续。本文件记录本机合成候选与实际验证，不代表生产、真实短信/微信或Mac验收。最新接续见[进度](../进度.md)。

## 用户流程

登录后展开“修改账号密码”，填写当前密码、新密码和精确一致的确认密码。成功会退出本账号包括当前窗口在内的全部旧登录，之后用新密码重新登录；不自动发放替代会话。其他员工的密码、会话、岗位及资料权限保持。

新密码沿用12至128个Unicode码点、最多512个UTF-8字节的既有规则；首尾空格、大小写及Unicode序列不trim或normalize，没有新增字符复杂度、历史或“不得与旧密码相同”的政策。确认不一致或长度不合规时界面不提交；主进程和服务端仍独立校验。

旧密码错误返回403验证失败，清除秘密输入后仍可重试，不误退当前有效账号。当前会话真正失效时才401清退。此功能依赖当前密码，不依赖SMS；短信未开通不会阻止本人改密，忘记密码/账号恢复仍按独立流程处理。

关闭、清空或换账号会清除三个输入，延迟到达的原生展开事件不擦刚填内容。请求提交后关闭面板不代表服务端取消；同一账号确认改密成功仍必须清退，迟到结果不能误退新的登录代次。网络或5xx导致结果未知时，提示请求可能已经完成、需用新密码重新登录核对，不自动重试或冒称失败回滚。

## 服务端及桌面边界

现有`POST /api/auth/password`只接受`{currentPassword,newPassword}`，没有可选userId或role。请求体读取后及异步密码计算完成后的事务中，重新核验发起会话、相同内部用户、有效状态及凭据hash/revision；CAS更新密码、递增版本及撤销该用户全部旧会话原子完成。存储失败不部分改密，限流尝试保留。

错误当前密码现在固定403 `VERIFICATION_FAILED`，缺凭据409；真实失效会话401。旧认证测试中只把错误密码的401契约精确改为403并追加错误码断言，保留原会话200、改后全部旧会话401、旧密码拒绝及新密码成功的原断言，未弱化验收。

既有手机号映射、成员角色、原会话元数据不因改密更换。旧手机号绑定/恢复证明、旧微信ready事务不能绕过新的凭据版本。沿用共享KDF并发与每账号10次/15分钟实验限制，不把该参数当成已批准生产政策。

改密阶段桌面增加一个`changeOwnPassword`窄操作，当时preload共29项。后续[人工开通](MANUAL_TEAM_ONBOARDING.md)使当前共37项、8个form、11处密码输入。主进程固定路径/参数/返回白名单，只返回`{signedOut:true}`，不会采纳额外token，成功同步清除主进程凭据；密码不持久化、不输出日志。界面独立账号/面板代次及跨关闭请求锁，防重复和迟到误退。
