# 正式身份方向：手机号密码＋微信扫码

日期：2026-11-15；来源：用户对正式账号选项回复“2加上微信扫码登录？”；按“手机号＋密码，并增加微信扫码登录”落实为产品方向。当前本机用户名演示账号仅作测试，不冒充正式手机号验证或微信接入。

## 1. 同一个员工账号，两种登录方式

服务端内部User ID不随手机号或微信身份变化，团队/角色/项目/设备/席位都关联该内部ID。手机号验证成功后建立手机号凭据；微信通过可信授权关联同一个内部ID。登录成功不意味着自动加入团队、获得合伙人或获得付费席位。

不能按微信昵称、头像、客户端提交的手机号或未经证实的UnionID自动合并用户。手机号换绑/微信绑定解绑/账号恢复都需当前强认证及必要的短信验证，记录审计事件，并按风险撤销旧会话；旧手机号不能自动取得后来持有者的客户权限。

## 2. 手机号＋密码

- 生产手机号规范化为统一表示，服务端短信挑战绑定操作用途和账号；短期、单次、次数限制、防重放，发送频率和验证错误限额分别控制。
- 注册/激活、登录、找回、换绑分别设计；不把“发送成功”当成已验证，也不在真实供应商不可用时返回虚假成功。
- 密码沿用成熟自适应哈希和服务端会话机制，不明文保存；日志不含验证码、口令、令牌、原件或完整手机号。
- 短信提供商、签名、模板、计费、实际发送及主体资质未具备前，只能用明确的测试适配器和合成号码验协议；不能向真实号码发送或声称真实验证通过。
- 管理员邀请不能设置被邀请人的正式永久密码；团队邀请、账号验证与职级授权分别完成。

## 3. Windows/Mac的微信扫码方案（候选设计）

`桌面创建短期登录事务 → 系统浏览器打开受限微信授权页 → 微信扫码授权 → 官网国内HTTPS回调 → 服务端校验state并换取微信身份 → 已绑定账号登录或首次强验证关联手机号 → 发起桌面实例单次兑换 → 审易会话 → 团队/任务/设备/订阅检查`。

- 通过微信开放平台的适用网站应用能力接入，不将公众号、小程序OpenID或微信支付商户身份直接混用。
- 原生桌面借助系统浏览器授权。桌面只为固定微信认证域名、路径、已配置应用及本产品HTTPS回调提供窄入口，不开放通用`openExternal`或放宽renderer网络；官网将来其他网页链接另行定义范围。
- AppSecret和微信令牌留在国内服务端；renderer、安装包、Git和日志不含这些秘密。客户端不能拿AppSecret直接换用户身份。
- 随机`state`绑定账号登录事务、有效期和最初客户端；微信code仅一次交换，回调和桌面兑换都防重放。桌面自己的兑换层可采用nonce/PKCE等证明，不能假定微信接口本身支持PKCE。
- 微信身份键以`(appId,openid)`区分；UnionID是否返回及跨应用关联条件按实际官方权限和真实响应验证，不能把它当始终存在。
- 首次微信授权不等于已验证手机号。建议首次扫码需对现有员工账号重新认证并验证手机号，再明确确认关联；同一手机号已有账户时不能静默覆盖绑定。
- 扫码取消、过期、用户未绑定、手机号冲突、两端并发、旧账号解绑、服务端撤销和异常回调都要有可恢复状态；缺少配置时展示真实未开通状态，不放一个总返回成功的二维码。

## 4. 外部前置与权限

经营主体/省份确认 → 域名实名和国内部署/HTTPS回调 → 核对微信开放平台认证及网站应用审核条件 → 获取相应应用ID与服务端凭据 → 短信主体签名/模板和服务开通 → 隔离测试 → 真实授权联调与验收。

截至本次仍无域名、服务器、短信供应商或微信应用资料。不得代购、代签、自动申请或索要明文密钥；所需费用/审核周期按实际官方申请页面核对，不预先保证个人主体可申请或给固定收费日程。微信登录与微信支付是两个独立接入，不因其中一个获批就声称另一项可用。

## 5. 测试和完成边界

先实现可替换的手机号/SMS与微信身份适配器契约及合成端到端测试；测试中模拟供应商必须显式标注。覆盖验证码用途/期限/次数/单次性、限流、手机号重复和换绑、OAuth state/code/桌面凭据重放、错误AppID、取消/超时、账号关联冒领、设备及团队权限不随登录方式提升。

只有真实短信签名/模板、微信应用审核/配置、真实授权回调、Win/Mac系统浏览器回到桌面、绑定和退出/撤销分别有证据，才可称对应生产能力验收；本机用户名密码流程不算这些关卡通过。

## 7. M2已实现的本地身份边界（2026-11-15）

本节记录`37476da`身份基线，后续桌面变化见第8节。分支`codex/phone-wechat-identity`接续`31b9369`。`server/team/identity-schema.sql`只给具有M2隔离库标记的数据库增加身份表；拒绝未知库，不迁移旧平台或客户数据。现有合成库升级前已做SQLite在线备份，位置见根目录`进度.md`。

| 入口 | 当前行为 |
|---|---|
| `GET /api/auth/methods` | 只返回本机预览能力布尔值，无供应商秘密；默认短信、微信、恢复均false |
| `POST /api/auth/phone/challenges` | 首绑或恢复用途；验证码上下文HMAC、5分钟、最多5次、发送限额；无SMS适配器直接503 |
| `POST /api/auth/phone/bind` | 当前有效会话＋当前密码＋本次验证码，只给当前员工ID首次绑定已验证手机号；不覆盖/合并其他账号 |
| `POST /api/auth/phone/login` | 已验证手机号＋密码，复用同一内部员工ID、团队与任务范围；异步计算后重新校验凭据与账号状态 |
| `POST /api/auth/phone/reset` | 默认关闭；除短信证明外，必须由可信恢复适配器批准额外恢复凭据；成功原子改密并撤销旧会话，不采用短信单独找回 |
| `POST /api/auth/wechat/transactions` | 创建5分钟事务、随机state及轮询秘密；校验应用配置和微信授权URL；保存摘要 |
| `GET /api/auth/wechat/callback` | 仅准确GET回调例外允许跨站；校验state、code单次性、AppID，异步交换后拒绝被取消/过期事务；不在回调页面输出身份或令牌 |
| `POST /api/auth/wechat/transactions/:id/status`、`cancel` | 持本事务秘密查询/取消；不向其他发起端泄露身份 |
| `POST /api/auth/wechat/transactions/:id/link` | 首次关联需当前已验证手机号账号的会话、当前密码及发起端S256证明；不自动建用户、入团队或加职级 |
| `POST /api/auth/wechat/transactions/:id/exchange` | 同一发起端证明、当前身份映射和账号版本；仅成功一次发放审易会话 |

供应商通过服务端`identityProviders`显式注入。SMS需要`phonePepper`（至少32字节）与`sms.send`；微信需要`appId`、准确HTTPS `redirectUri`、`createAuthorizationUrl`与`exchangeCode`；恢复需要`recovery.authorize`。这些是测试适配契约，不是已经完成某家供应商SDK或真实发送。pepper和AppSecret不得写入Git或桌面。当前启动器没有注入这些供应商。

桌面新增4个窄操作：能力读取、手机号登录、请求首绑验证码、确认首绑；总计12项IPC白名单。默认仍可用明确标记的合成演示账号，也可切换手机号＋密码。登录后首绑面板按服务能力禁用；换手机号、退出、401及操作完成会清空验证上下文和秘密字段。微信入口现在始终禁用：未配服务显示“未开通”，即使服务已配也显示“桌面待接入”，因为系统浏览器往返尚未实现。没有二维码或成功占位响应。

验证：完整可移植子集564/564；其后新增的2项桌面状态回归和6项确定性竞态通过（最新桌面身份15＋竞态6合计21/21；与564有重叠，不重复累计）。独立手机号21、微信19、HTTP3均通过。HTTP中微信回调使用直接派发的合成HTTPS Request，轮询/兑换走真实loopback HTTP；不是微信平台、真实TLS或手机测试。真实Electron验证手机号模式、未配SMS/微信禁用、令牌不进renderer和退出清空，独立安全agent复核无剩余P1/P2。精确命令/日志见`进度.md`。

下一检查点仍是M2：桌面窄系统浏览器入口和微信事务往返、首次关联确认界面、注册/激活及恢复政策。真实供应商、HTTPS回调域名、手机和Mac实机分别留待具备条件后验收。设备绑定属于M3，不能把身份S256证明当作电脑绑定已完成。
