# 审易试点前双人评审单

本次用合成资料走查采集、底稿、账务与官网。产品负责人确认权限范围、操作体验及对外产品口径。米老师确认采集和核对流程的业务表述，记录仍需决定的审计规则。详细操作按各入口说明执行。

收到 Windows 便携评审 ZIP 时，按说明完整解压，双击下表对应入口。合成演练资料位于解压目录的 `review-runs`。 [评审包说明](../README-Owner-Review.md)

## Windows 走查路线

| 顺序 | 启动入口 | 当场确认 |

| 3. 订阅、席位与退款受理 | [Start-Team-Billing-Candidate.cmd](../Start-Team-Billing-Candidate.cmd) · [M5 账务演练](M5_LOCAL_ACCEPTANCE.md) | 产品负责人确认年续费、增购、恢复兑现和退款受理。用该轮预置订单核对席位、到期日和原收款时间。米老师可核对账务角色取得的权限范围。 |
| 4. 官网年费与增购下单 | [Start-Team-Website-Checkout-Candidate.cmd](../Start-Team-Website-Checkout-Candidate.cmd) | 产品负责人以启动窗口显示的合成技术管理员登录并绑定本轮电脑，从桌面打开专用官网窗口，分别完成年费和增购待处理模拟订单，再回桌面核对同号。只核对下单体验，不收款、不兑现权益。 |
| 5. 官网口径 | [Start-Website-Preview.cmd](../Start-Website-Preview.cmd) · [官网预览说明](../website/README.md) | 两人核对官网是否说清四职级、年费与席位、桌面版本以及当前下载和购买状态。米老师检查关于资料核对和审计职责的表述，产品负责人确认面向用户的说明。 |

采集的四个角色在同一新候选中依次登录，保持同一批合成数据。账务另开独立候选。遇到实习生或助理看到未指派的任务、全项目资料目录或未授权的原件，或未获核对权的合伙人出现原件核对入口，暂停该项并记录当时的角色、项目和界面。出现报告生成、审批或签发入口，或界面把采集核对表述为审计结论时，先留证交米老师和产品负责人核对授权与业务口径。

## 官网下单走查

1. 双击 `Start-Team-Website-Checkout-Candidate.cmd`，按启动窗口显示的合成技术管理员账号和密码登录，并完成本轮电脑绑定。每次启动是新的独立环境；请在同一轮完成下面两类订单。
2. 在“订阅与席位”中打开官网年订阅入口。专用官网窗口应显示本团队名称和本地模拟提示。核对目录年费与所选席位，明确创建模拟订单，记录待处理订单的编号、金额和席位。关闭该官网窗口，回桌面选择年费订单并刷新，核对同一编号和金额。
3. 从同轮桌面打开“在官网增购席位”。选择 1–1000 席中的新增数量，取得服务端按当前订阅剩余期限计算的报价，核对金额、席位有效期和“报价确认截止”。修改数量后旧报价应失效，需重新报价。在截止前明确确认建单，再将回执中的订单编号、金额和到期日与桌面的增购席位订单刷新结果比较。
4. 增购回执显示的“订单锁价截止”属于已保存订单的窗口，与建单前的“报价确认截止”分别核对。提交后若提示结果尚未确认，先使用只读核对找到原订单；不要连续创建订单。授权失效时回桌面核对记录后，再重新打开官网入口。
5. 两类订单均应保持“待处理（模拟）”。此入口没有真实支付，不增加席位、不延长订阅；账务数据如需走查验款或兑现，使用原账务入口的独立合成环境。结束时关闭本轮桌面并确认启动窗口已退出。

## 接下来如何进入试点

合成评审回执只记录上述走查。获准试点须另记团队和人员范围、允许使用的脱敏样本、隔离环境、试点期限与资料处置方式，再由双方确认。实际客户资料、迁移和外部发布按各自授权办理。

首管理员完成激活后，产品负责人逐队登记结束时刻和席位上限。核对审批返回的期限及席位，再由首管理员走查首份邀请。仓库进一步参考：`docs/MANUAL_TEAM_ONBOARDING.md` 的“受管服务首个试点”章节。

米老师在本单签核的是专业流程和待定规则，审计报告仍按实际专业审批和签发权限另行处理。产品负责人在本单签核的是应用范围与试点建议。正式发行另验签名安装、Windows 和 Mac 实机、生产付费与退款、官网及国内上线手续，再核对实际访问地址与版本。
