## 当前可以做什么

对服务端已完成可信登记的项目，按当前员工身份和该项目的显式授权显示采集入口。项目创建者可管理其他普通经理、合伙人的采集读取、采集管理及资料核对权限；获采集管理权者可新建采集任务，再通过既有任务分工明确指派本团队实习生或助理。获读取和核对权者可查看指定任务的提交及保存原件副本。

这里的“核对”是查看采集资料，不形成审计通过、专业复核或报告签发结论。实习生、助理仍只收到自己获指派的任务和本人原件，技术管理员身份不自动获得审计资料。

**尚未开放正常项目创建。** 经理、合伙人均可建项目以及创建者管理授权的分工已确认；旧正式立项必须关联最新结果为中标的报价。是否允许先建采集工作区、正式立项再沿用原规则，仍待产品负责人选择。本轮没有创建项目的按钮或RPC，`POST /api/teams/:team/projects`返回404。测试中的项目是明确的受信任合成登记，不能作为正常新建流程的验收证据。既有项目不会自动登记、猜测创建者或扩权。

## 权限如何生效

| 能力 | 必要条件 | 不附送的能力 |
|---|---|---|
| 管理本项目采集授权 | 有效普通经理/合伙人、当前项目owner、当前密码及版本检查 | 其他项目权限、owner转移或自助恢复 |
| 读取本项目任务 | 当前项目显式read | 任务管理、提交及原件核对 |
| 创建采集任务、沿用任务分工 | read和manage | 提交及原件核对、自动指派员工 |
| 查看提交、保存核对原件副本 | read和独立review | 管理人员授权、审计通过或签发 |

权限在服务端执行，过滤先于搜索、分页及数量判断。新接口要求严格设备绑定和当前业务租约，即使测试服务全局关闭设备要求也不能绕过。项目DTO只有id、title、status、revision和四项能力，不下发完整项目结构或财务资料。owner历史记录与当前授权分开；降职、停用撤销owner/review，重新升职不会复活它们，正常改密或换机也不永久剥夺合法owner。

撤销某人的项目采集访问，会在同一事务撤销该项目的管理/核对、任务指派及附件授权，并使其旧会话、租约和未用设备挑战失效。确有任务指派变化时对应任务版本只递增一次。其他项目、其他员工、身份映射、电脑绑定、已提交原件和历史记录保持；合法落盘副本不能靠远程撤权收回。

新建任务只接收标题和说明，标题最多160字，说明最多4000字并保留换行和缩进。服务端生成UUID并记录对应任务ID的事件，版本过期、重复无变化、越权或状态变化均拒绝；不复制专业底稿、不生成编号或自动分工。

## 客户端与存储

客户端增加“项目采集与资料核对”面板，沿用已批准视觉方向。授权、新建任务都需明确确认；授权另须当前密码。关闭、退出、断网、旧请求返回时清理秘密和旧选项；结果未知不自动重发，成功后刷新失败单独提示。

9个窄RPC使当前preload总数为76，页面共13个表单、19个密码输入。核对下载在GET后及保存前重新检查权限，最后用不读取BLOB的HEAD确认，才写入用户选定路径。空HEAD404按明确拒绝处理；其他空错误及401仍按既有失效规则处理。

新增3表、2索引、11触发器，当前54表、105个非SQLite内部对象。sidecar记录不可变创建来源；独立ACL保存owner/review；事件保存任务创建和授权变化。既有read/manage与本人采集路径继续复用，不把新表当成旧库迁移或正常创建入口。
