# 报价快照迁移预览 v0.1

`dist/quote-migration.js` 是纯计算模块，不写 localStorage，不创建项目，不连接服务器；当前尚未接入页面。只使用用户明确指定的事务所标识和迁移操作人，调用 `QuoteMigration.preview({legacyRecords, existing, firmId, actor, migratedAt})`，返回不可变的预览。

## 原则

- 原记录以 `original` 在迁移结果中完整保留，包含所有原始财务字符串、原规则、工时、地区结果、报价调整和计算结果；规范化后的首个修订额外保存整数分、百分比基点、规则快照及总额。不能用丢失精度或无原记录的结果声称无损迁移。
- 对每条历史地区规则校验省级编号与名称的对应关系，支持标准全名和常用简称；名称不匹配或地区目录不可用时拒绝迁移并保留原始数据，不能依赖上游 UI 校验。
- 严格使用保存的历史财务、规则和工时，复算各已保存地区结果（含计费基数、金额及分段明细）和预算，验证所选预算、手工或地区基准，再检查优惠、税额及总额。不使用当下地区规则，也不推断历史规则的官方有效性。无法复算或结果有差异即拒绝迁移。金额、时间或记录版本不支持时返回错误，原始记录仍由调用方保留。批次任何错误都不返回新增或合并结果，需逐条排查；不做静默修复。
- 原报价 ID 用作新报价 ID，报价的项目编号始终为空；必须由业务流程显式创建或关联项目。重复迁移时原始内容相同且同一事务所，保留已有全部修订并跳过；同 ID 不同内容拒绝。不同事务所的现存记录不被接受。
- `existing` 必须由可信存储提供完整的同所迁移记录；只输入当前子集无法发现其他记录的编号冲突。正式存储需实现跨全库唯一约束或复合键、身份认证、租户级授权、原子写入和审计日志。本地对象字段不构成隔离或证据防篡改。
- 迁移操作者和事务所标识由调用方明确提供，不代表其身份已验证；迁移并不代表原价已审核。历史 `savedAt` 保留在原记录中，新修订的 `createdAt` 取调用方提供的实际迁移时间，操作者为迁移人而非推断原操作者，须在后续 UI 明示。未经用户确认不可执行实际迁移。
- 原始快照可能含敏感信息，应按数据分类和事务所保密要求处理。发布与迁移前必须另做备份、恢复、并发、授权、脱敏样例及历史版本一致性测试。
