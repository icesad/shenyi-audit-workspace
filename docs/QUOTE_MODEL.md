# 报价模型 v1 设计说明

此模型为 G1 的领域层原型，独立于页面、存储和权限系统，**尚未接入现有 UI 或数据持久化**。仅定义报价数据与修订的可检验约束，不声明生产验收完成。

## 字段字典

| 字段 | 含义 |
| --- | --- |
| schemaVersion | 模型格式版本，当前整数 1；未知版本拒绝读取。 |
| id / firmId | 报价及事务所标识，由调用方生成；租户隔离必须由服务端另行执行。 |
| revisions | 按序追加的修订数组。序号从 1 开始；每条包含状态、UTC 时间及操作人。 |
| details.client | 客户标识、名称和所在地快照。 |
| details.auditYear / serviceType | 审计年度和服务类型。 |
| details.financial | 资产、营业收入、净利润快照；均以**整数分**存储，净利润允许负数。 |
| details.rules | 规则编号、版本及完整参数快照，至少一条；不负责核验规则是否官方有效。 |
| details.adjustment | 报价基础、优惠基点、附加费分、税率基点和调整理由。100 基点为 1%。 |
| details.result | 基础、优惠、小计、税额、合计的整数分以及计算明细；金额组合和比例四舍五入到分。 |
| details.projectId | 可选、显式提供的已有项目标识；模型不会创建或推断项目。 |

`create` 创建草稿；`append` 用期望修订号追加新草稿或状态修订，状态修订不能改变业务内容；`restore` 验证导入并深冻结副本。状态为业务建议，需要事务所确认。修改已发送/已接受报价将创建新草稿，不覆盖历史。

## 边界

- 对象冻结仅约束本次 JavaScript 进程；落盘后的追加只读、权限、真实性、跨租户隔离、撤销、并发一致性须由未来服务端和数据库保障。`expectedRevision` 是调用接口的乐观检查，无法替代数据库事务和条件写入。
- `firmId` 只是数据字段，不是授权凭证；不能信任客户端提供的身份。
- 对规则快照只做 JSON 结构验证，并不验证规则内容、发布状态或现行法律效力；规则核定由规则模块和人工流程负责。
- 此阶段不提供迁移、审批、身份认证、持久化、报价单、资料上传或项目创建能力，不应与功能已上线混淆。
- 保留的精度和税额计算与现有示例一致；实际含税、税率和舍入制度需业务确认。
