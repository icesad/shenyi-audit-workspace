# 席位增购、报价和收款

本地服务端候选基于[邀请预留与容量](INVITATION_SEAT_CAPACITY_CONTRACT.md)和[年续费订单](ANNUAL_ORDER_SIMULATION_CONTRACT.md)。用户确认增购对齐团队原到期日，按精确剩余时间折算，整单向上取整到分。[订阅与席位决策](SUBSCRIPTION_SEAT_DECISION.md)

本团队技术管理员可查合成目录、为启用年期中的团队建单、查询与主动查单。操作继续要求当前团队技术管理员资格和已绑定设备。建单只收请求编号、方案编号与版本、数量。服务端计算金额并锁定认购数量、报价时点、当时的订阅版本及原到期日。相同请求重试返回原单，数量或方案不一致则拒绝。

候选公式为席位年单价（分）乘席位数，乘剩余毫秒数，再除以从报价时点起一个北京时间自然年的毫秒数。用整数计算整单后向上取整一次。当前报价最多有效 15 分钟，且不晚于锁定到期日。提前续费可使剩余时间长于一年，候选按全部剩余时间计算。正式单价、分母、报价时效及数量限制仍待确认。

签名收款通知和可信查单沿用同一合成网关，校验商户、订单类型、订单号、锁定金额和币种。订单号、支付事件和交易号跨续费及增购防复用。首次验证的收款事实独立保存。增购必须在锁价窗口内付款，原期限仍未结束且当前订阅覆盖锁定区间时，原子写入一份容量记录作为兑现事实。起点为首次可信收款确认时刻，终点为原到期日。续费后的更晚日期不会改变既有报价或已购容量。

有效付款的通知可晚于报价时效，只要原期限仍有效。付款超出报价窗口、原期限已结束或变更不再覆盖锁定时段时，订单维持已验收款待处理，容量不新增，也不自动发起退款。提交故障后的同一通知可继续补偿；完成后重放返回原记录。验签成功且付款时间可信的情况下，实际可用容量仍以服务端当前时间计算。候选仅使用本机测试和合成价格。

- `GET /api/teams/:teamId/billing/seat-offer` 返回当前合成方案。
- `GET /api/teams/:teamId/billing/seat-orders` 列本团队订单。POST 创建带锁价的订单。
- `GET /api/teams/:teamId/billing/seat-orders/:orderId` 返回订单和已兑现容量记录。
- `POST /api/teams/:teamId/billing/seat-orders/:orderId/reconcile` 经可信查单来源补收款。
- `POST /api/teams/:teamId/billing/seat-orders/:orderId/resume-fulfilment` 接受空 JSON，由当前持钥的本团队有效技术管理员恢复已验收款的兑现。原收款时间、锁定到期时刻及数量保持一致。报价和年期仍须满足原条件，关单及退款异常进入复核。
- `GET /api/teams/:teamId/billing/seats` 返回按期限计算的当前余额。
