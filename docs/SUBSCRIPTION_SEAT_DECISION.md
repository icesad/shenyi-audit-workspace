# 团队年订阅与员工席位决策

日期：2026-11-18（Asia/Shanghai）。状态：下列席位、业务到期、到期管理、账务操作人和续期日历政策已由产品负责人在当前会话正式确认；本文为这些政策及其边界的canonical记录。[产品需求7.1](TEAM_PRODUCT_REQUIREMENTS.md#71-权益和席位)引用本文件。

订阅基础见[M5A合同](SUBSCRIPTION_FOUNDATION_CONTRACT.md)，17个业务数据写入口见[M5B合同](SUBSCRIPTION_BUSINESS_EXPIRY_CONTRACT.md)，16个现有团队管理写路线的到期分类见[M5C候选](SUBSCRIPTION_MANAGEMENT_EXPIRY_CONTRACT.md)。历史仍按原权查阅／导出，撤权和原安全流程保留。M5仍在进行中，完整订单／续费／支付、自然年算法及桌面界面尚未实现，不代表全M5验收或已经上线。

## 1. 已确认：席位计数

用户原话：“只计启用的业务成员；纯技术管理员不占席位，兼任业务职级只计一席。”

- 启用的实习生、助理、项目经理、合伙人均属于业务成员，每位计一席；停用业务成员不计入启用业务成员席位。
- 纯技术管理员不占业务席位；管理员经既有审核兼任业务职级且处于启用状态时，只计同一成员的一席，不因双重身份重复计席。
- 席位计数不授予业务职级或资料权限。管理员兼任职级的审核、账号与团队归属继续遵守原规则；不因技术管理员不计席而允许其查看审计资料。

## 2. 已确认：到期动作边界

用户原话：“年订阅到期暂停新增和修改，已授权历史可查阅/导出，保留主动续费入口。”

- 到期暂停业务新增和修改；已授权历史仍可查阅及按原权限导出，界面保留用户主动续费入口。
- 历史访问必须仍满足当前有效的账号／团队成员、设备、项目范围、模块授权和资源状态；曾经获过权不等于永久访问。立项来源、底稿导出仍须read与export双权，其他模块沿各自原有规则，不新增“到期通用导出权”。
- 纯技术管理员不因到期政策获得审计资料权；到期或续费均不自动解冻、不运行账表校验、不写入底稿或开放未确认的专业操作。
- 首次把旧本机来源、资料或底稿迁入团队仍涉及新增或修改。本次只确认已授权历史的查阅／原权导出，不承诺到期可首次迁入。
- 续费入口保留不等于确认购买入口位置、付款人、订单操作权或自动扣款；入口不能展示用户无权查看的财务资料。

## 2.1 已确认：到期管理操作

用户原话：“只允许停用、撤权和原规则下的换机／安全处理；邀请、启用、升职及增权须先续费。”

- 到期仍可按原有效管理员／负责人权限停用和撤权；订阅不阻断原规则下的换机审核与安全处理。
- 邀请、启用、升职及增权须团队订阅有效。混合增权与撤权不能仅因含有撤权而放行；不因续费取消原审核、密码、项目或模块授权要求。
- 登录、改密和安全恢复继续遵守原身份与审核规则；纯技术管理员不因该政策获得业务资料。
- 现有管理路线已进入M5C本地候选。按同目标的独立授权原子判断增权，不能按名称排序、净位数或read前提掩盖潜伏授权；只覆盖现有入口，不新增enable或平台购买先后规则。完整商业化与生产验收仍未完成。

## 2.2 已确认：本团队账务操作人

用户原话：“本团队的技术管理员。”

- 本团队的技术管理员可查看本团队订单金额、创建主动续费及增购席位订单；业务职级本身不授予账务权限。
- 账务权限不授予任何审计资料、项目结构或专业动作。跨团队、退款、开票和其他财务操作不从这条决定推导。
- 这是下一片实现的政策；M5C没有新增订单／支付HTTP或界面，没有真实收款，也不自动扣款。

## 2.3 已确认：单年续费的起算与日历

用户确认采用提问中的完整规则：“未到期从原到期时刻顺延，已到期从可信收款确认时刻起算；按北京时间计算一个自然年，2月29日对应次年2月28日同一时刻。”

- 服务端保存UTC时刻，续期日历按已确认的北京时间解释；不以客户电脑时区或时钟计算权益。
- 只有可信收款确认才可执行续期；未验签回调、客户端成功页或手工改日期不能授予有效期。
- 该决定尚未实现为算法或支付闭环；未确认的价格、容量、席位增购折算、退款、宽限和购买入口仍保留边界。
