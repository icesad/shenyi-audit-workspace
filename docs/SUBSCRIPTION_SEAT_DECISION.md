# 团队年订阅与员工席位决策

日期：2026-11-18（Asia/Shanghai）。状态：下列两条政策已由产品负责人在当前会话正式确认；本文为这两条政策及其边界的canonical记录。[产品需求7.1](TEAM_PRODUCT_REQUIREMENTS.md#71-权益和席位)引用本文件。

两条政策现进入[M5A服务端基础候选](SUBSCRIPTION_FOUNDATION_CONTRACT.md)：已实现可信区间持久化、有效业务计席、本人状态及一条新建入口的订阅guard。M5仍在进行中，其他业务写出口、完整续费／支付和桌面界面尚未实现，不代表全M5验收或已经上线。

## 1. 已确认：席位计数

用户原话：“只计启用的业务成员；纯技术管理员不占席位，兼任业务职级只计一席。”

- 启用的实习生、助理、项目经理、合伙人均属于业务成员，每位计一席；停用业务成员不计入启用业务成员席位。
- 纯技术管理员不占业务席位；管理员经既有审核兼任业务职级且处于启用状态时，只计同一成员的一席，不因双重身份重复计席。
- 席位计数不授予业务职级或资料权限。管理员兼任职级的审核、账号与团队归属继续遵守原规则；不因技术管理员不计席而允许其查看审计资料。

## 2. 已确认：到期动作边界

用户原话：“年订阅到期暂停新增和修改，已授权历史可查阅/导出，保留主动续费入口。”

- 到期暂停业务新增和修改；已授权历史仍可查阅及按原权限导出，界面保留用户主动续费入口。
- 历史访问必须仍满足当前有效的账号／团队成员、设备、项目范围、模块授权和资源状态；曾经获过权不等于永久访问。立项来源、底稿导出仍须read与export双权，其他模块沿各自原有规则，不新增“到期通用导出权”。
- 纯技术管理员不因到期政策获得审计资料权；到期或续费均不自动解冻、不运行账表校验、不写入底稿或开放未确认的专业操作。
- 首次把旧本机来源、资料或底稿迁入团队仍涉及新增或修改。本次只确认已授权历史的查阅／原权导出，不承诺到期可首次迁入。
- 续费入口保留不等于确认购买入口位置、付款人、订单操作权或自动扣款；入口不能展示用户无权查看的财务资料。

## 3. 仍待确认及实施前边界

| 未决项 | 本次未作出的决定 |
|---|---|
| 定价与购买入口 | 价格、优惠、试用、税费、官网或客户端购买位置、谁可发起续费和付款 |
| 席位容量与变更 | 席位上限、超额处理、增购折算、减席退款及启用／重新启用时的容量处理 |
| 续期与恢复算法 | 提前或过期续费的起算、恢复时刻、年限叠加、闰年边界和宽限期 |
| 退款及资料保留 | 退款／拒付的权益处理、历史资料保留期限与删除规则 |
| 到期管理写操作 | 是否允许新增、撤回或调整授权，以及邀请／激活、成员启停、设备审批和席位调整等操作的具体分类与范围 |

上述未决项不能由“只计启用成员”“历史可读／原权导出”或“主动续费入口保留”推导。实施时应在操作矩阵中区分已确认政策、工程选择和未决政策；可继续合成模型与默认拒绝实验，涉及收费口径、权限扩大或资料归属的未决政策再单独确认，不把候选方案写成已批准规则。本片不豁免完整M5验收、支付与生产门槛；自动扣款仍需独立条件和授权。
