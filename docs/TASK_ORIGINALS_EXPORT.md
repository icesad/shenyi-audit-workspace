# 单任务所选原件导出

2026-11-16，M4E 本地候选，分支 `codex/task-originals-export`。功能位于正常团队桌面，规则见[执行合同](TASK_ORIGINALS_EXPORT_CONTRACT.md)；旧端的[资料保全与恢复](MATERIAL_PRESERVATION.md)保持独立。

## 使用方式

1. 在“我的采集任务”选中当前任务，从“我的提交记录”勾选需要的提交。经理或合伙人在获授权项目的“采集资料核对”中，同样先选任务，再勾选已经加载的记录。
2. 核对页面显示的所选份数和总大小，点击“导出所选原件包”。每次1–20份，单份沿原12 MiB上限，合计不超过64 MiB。只导出明确勾选的记录，不自动选全部历史、隐藏分页或其他任务。
3. 程序重新读取当前授权清单，逐份取回并核对实际原件大小和SHA-256，通过后才打开系统保存框。
4. 选择保存位置。程序在发布前再次核对同一任务、同一组所选记录、权限及版本。任一原件失权、缺失、损坏或状态变化都会停止整个导出，不悄悄省略部分文件。
5. 成功后显示所保存文件的名称并清除本次选择。取消保存框不创建目标文件，不自动重试；可以重新勾选后发起新的导出。

正常下载权保持：任务已提交、已关门或项目冻结时，可下载的原件仍可导出，不要求能继续上传。归档或当前权限已失效则拒绝。

## 谁能导出

- 本人入口同时要求当前任务可见、该记录由本人提交，以及该原件的个人下载授权仍有效。“我的提交记录”中看得到旧记录，并不保证现在仍有原件下载权；有一份无权就整包拒绝。
- 项目核对入口要求当前有效的经理／合伙人身份，以及该项目显式的读取和独立资料核对权限。项目所有者、采集管理权或技术管理员身份不代替原件权；获批兼任业务职级的管理员也须取得相同项目权限。

客户端未接收其他项目目录、完整资料树、隐藏成员名单或财务字段。界面隐藏按钮不是授权依据，服务端每次重新核权；复制接口参数也不能扩大范围。换账号、换任务／项目、关闭面板或业务暂停会清除当前选择，迟到结果不污染后来的账号和操作。

## 包内内容

ZIP只含规范UTF8的 `manifest.json` 和所选原件。清单保留原提交ID、附件ID、原文件名、字节数、SHA-256、提交时间与当时的最小任务上下文；项目核对包另含该入口本来可见的提交者姓名／ID及项目修订号。本人包不含他人的提交者身份或项目ID。

原件内部路径为 `originals/0001-<原提交ID>.bin`，序号对应清单的文件顺序。它让同名原件、大小写不同的ID及Windows设备名都能安全区分；原提交身份未重编号，原件没有转换格式或重写Office。需要在包外打开文件时，可按清单中的 `filename` 给解包副本恢复原扩展名；保留原ZIP作为核对来源。

这是**所选资料副本和提交摘要**，不包含全部历史、完整项目／软件备份、专业审核事件或团队资料迁入机制。清单不形成审计通过、签发或“服务器证明文件已经保存”的事实。包和原件未加密，应由有权人员妥善保管；SHA-256和CRC32用于完整性检查，不是第三方签名。

## 失败与原有文件保护

资料先在主进程内核验；原件字节、包字节、系统路径、token和设备密钥不进入界面。保存前的批量核权不读取原件BLOB，使用当前持钥会话及业务授权。

新导出在目标同目录创建本次随机临时文件，完整写成、同步并核对当前会话后再原子发布。写入或发布失败不先截断原有目标；取消、核权失败或账号变化时不发布目标。若操作系统连本次临时文件也无法删除，会提示可能残留的临时文件名，同时保留原登录失效／会话变化原因；只处理提示中本次文件。

服务端授权检查与本地发布不可能组成一个分布式原子事务。最后核权之后仍存在极短的本地发布边界，已经合法保存的副本无法承诺远程追回。
