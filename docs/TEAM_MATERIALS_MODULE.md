# 团队资料清单、历史与原件

资料清单使用独立的查阅、首次导入、核对、关门／重开权限。项目负责人可以输入当前密码，逐项给自己或本项目合格经理／合伙人授权；负责人、职级、技术管理员或归属审核身份本身均不附送资料权限。关门／重开可以与核对分开授予。

查阅权限包含完整清单、全部操作历史及所有历史引用原件，包括已移除和旧代原件。实习生、助理继续只使用明确指派的采集任务，不向他们下发完整资料结构。原来的采集读取、管理和核对权限与本模块分开。

## 使用路径

1. 先按 [旧正式项目归属登记](LEGACY_PROJECT_REGISTRATION.md) 完成产品负责人审核，核对所属团队、原项目 UUID、固定编号与首位负责人。旧经理姓名只是历史文字。
2. 负责人登录团队桌面，在“项目采集与资料核对”选择项目，展开“资料清单、历史与原件”。查找授权对象，逐项勾选权限、确认并输入自己当前密码。导入、核对或关门权限均须同时具有查阅权限。
3. 在旧版已保存的正式项目资料区，按 [资料保全说明](MATERIAL_PRESERVATION.md) 导出完整保全 ZIP。试用资料包不能迁入；真实客户资料上传前仍须相应授权，目前只使用合成数据。
4. 获首次导入权的员工选择 ZIP，核对旧项目快照、UUID、版本、关门状态及当前／历史原件数量，再明确确认并输入当前密码。只允许导入同 UUID 且团队资料区为空的项目，不覆盖已有记录。
5. 导入成功后刷新清单，可以按标题或状态查阅层级，展开“全部资料操作历史”查看旧代及已移除记录，点击相应“保存原件”经系统保存窗口落盘。原件不自动打开；正文和原文件路径不通过通用接口暴露。
6. 获核对权者选择具体资料项，按原五种状态填写证据或理由并确认。获关门／重开权者独立操作，并重新验证密码；未满足原清单关门条件时会拒绝。关门不代表报告签发或审计意见批准。

每次写操作在发送前显示查询编号。遇到“结果未知”，恢复连接后只读查询原编号回执并刷新当前资料，不重新发送同一操作；暂时查不到回执不能证明在途操作最终失败。已发送的提交不能靠关闭面板撤回。取消尚未发布的导入时，软件如实显示临时分块清理结果；过期来源不可继续使用。

## 保留与边界

- 原始 `record.json`、旧版本、旧关门状态、全部历史及原件 UUID／字节保持；后续核对只通过原 `AuditChecklist.apply/gate` 产生新记录。当前可信账号 ID 另存审计，旧核对姓名不映射当前账号。
- 撤权、停用、换账号或设备暂停后清除旧正文与秘密；尚未完成的保存须重新核权，失权后不发布新文件。已经合法保存的副本无法由本功能远程收回。
- 冻结项目可按已有权限查阅，拒绝导入、核对和权限变更；归档项目拒绝访问。旧清单关门与团队项目冻结是不同状态。
- 当前只做首次完整迁入和原有核对／关门／重开；新增团队清单模板、换代、附件增删、采集提交关联叶节点及 Office 内嵌预览仍待后续实现，不自动生成任务或审计签发。
- 包上限沿用180 MiB，历史原件累计150 MiB／5000份、单份12 MiB，记录24 MiB。客户端按1 MiB分块并节流，最终服务端逐份执行旧入库正文校验，不以 ZIP 的 SHA／CRC 代替正文检查。
