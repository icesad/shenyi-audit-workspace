角色变更、移出团队、任务撤销后，服务端立即按新状态拒绝后续请求；会话/缓存和下载票据及时失效。本地已落盘资料的可撤回边界在客户端缓存政策中明示，首版不默认开放长期离线团队数据。

## 5. 账号与团队

采用独立身份服务或成熟身份组件，不能把当前 Sites/ChatGPT 平台登录当成售卖产品的账号系统；迁移部署后不信任外部请求伪造的平台身份头。

- 个人注册或邀请激活、账号验证、登录/退出、密码修改、找回、禁用、会话查看及撤销；正式采用手机号＋密码并增加微信扫码，按身份方案实现真实验证和显式关联，不把资料手机号当作已验证登录凭据。
- 团队建立、邀请、加入/退出、成员停用、角色和项目指派；邀请有有效期、单次使用、防冒领；禁止客户端自选合伙人。
- 密码用成熟库的自适应哈希，优先评估 Argon2id；不存明文、可逆密码或自制哈希。登录/重置限流，错误提示防枚举；找回令牌单次、短时，重置后失效旧会话。
- 会话由服务端验证，保护 Cookie/令牌、CSRF、日志和秘密；高风险改密、设备迁移、提升权限需再次验证；管理员 MFA 为建议项，实施规则经确认。
- 团队/项目字段是强制查询条件；文件对象、缓存键、搜索索引和备份同样隔离。后台运维不默认看正文，临时支持访问需明确授权和留痕。
- 记录谁在何时、以何权限，对哪个团队/项目/资料做了什么；日志避免密码、令牌和原件全文，日志管理权限独立。

登录标识已确认手机号＋密码和微信扫码；短信/微信接入资料尚未具备。账号恢复审批已确认：团队管理员审核员工，管理员本人由产品负责人审核，两者都须本人短信验证。[内建审批/签发/撤销链](RECOVERY_APPROVAL.md)已实现本机候选，真实服务缺SMS仍关闭；不能把找回密码当成换机授权。多团队、团队所有权交接及相关恢复细节继续待确认，不发布不可逆账户归属逻辑。

M2邀请激活候选见[定向激活方案](EMPLOYEE_INVITATION_ACTIVATION.md)：业务经理/合伙人＋独立邀请授权，或另行获批的技术管理员，才可邀请实习生/助理；两个可信来源独立核对，低权限误授grant也不越过采集边界。新员工本人验证设密，既有无团队账号须当前密码复用；已有任意业务或技术归属保守拒绝新增，不把它当成已批准的多团队商业政策。真实SMS及所有权恢复仍需各自完成，激活不自动分配业务资料或付费席位。

M2[个人会话管理](ACCOUNT_SESSION_MANAGEMENT.md)候选已按本账号范围实现列表和当前密码重验的撤销，四角色仅管理本人安全，不扩展业务或同事权限。稳定管理ID不等于Bearer或设备ID，旧登录时间不编造；电脑数/并发/断网规则后续已确认，见6.2；M3 Windows本地候选已接入，Mac、真实跨电脑、生产仍分层未验；最高审核账号恢复按首版决定延期。

已确认前期由产品负责人（当前用户）人工审核开通团队及首管理员，员工通过邀请激活。[人工开通候选](MANUAL_TEAM_ONBOARDING.md)已实现录入待审、密码＋CAS批准/拒绝/撤销、首管理员本人手机号验证设密和技术管理邀请；不因首管理员身份默认获得审计资料、签发资格或合伙人职级，也不把该选择当成真实客户开通/收款授权。没有公开自助授予开通审核权的接口；生产审核账号部署、真人/主体核对、真实SMS、多团队、所有权移交及恢复细则继续待完成。

[本人改密](PERSONAL_PASSWORD_CHANGE.md)候选已接桌面，旧密码错误可重试、确认成功后全部旧登录退出；该改密／恢复切片当时的14处秘密输入清空证据保留，当前整体规模以进度为准；默认SMS缺席不阻断当前密码修改，不混同短信找回。

[找回密码](PASSWORD_RECOVERY.md)入口已接可信SMS＋独立授权，新快照绑定手机号版本/验证时间，旧重绑挑战拒绝。内建审核切片当时的44窄IPC、9form、15处秘密输入保留为历史验收口径，当前整体规模以进度为准；批准票与密码在同事务核权/消费；缺真实SMS/生产审核人时仍不启用，不因为出现输入框就开放短信单独找回。

安全实现参考：[OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)、[Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)，2026-11-15 核验。具体依赖版本在实际选型时复核。

## 6. 桌面端和电脑绑定

Windows/macOS 同一产品，优先复用现有 HTML/JS/CSS 和原件读取器。[ADR 0001](adr/0001-team-runtime.md)已选择Electron＋Node24作为单一工程验证候选，Tauri仅保留备选；Windows本地入口按各切片合同已验。生产数据库／云资源、安装签名更新及Mac兼容仍未据此选定或验收。

### 6.1 绑定生命周期

`首次登录 → 二次验证/激活 → 客户端生成设备密钥 → 服务端登记公钥与设备名 → 服务端挑战验证 → 发放有时效、可撤销的设备/会话许可`。

上述生命周期已由M3 Windows本地候选实现并分层验证，不等于Mac／生产发行或硬件级私钥保护已验；也不是“获取 MAC 地址即可可靠锁电脑”。私钥由操作系统安全存储保护；硬件指纹只作风险辅助、尽量少采集并披露用途。复制安装目录、伪造客户端设备ID或回放旧挑战不能自动获得有效设备许可；本机管理员/被攻陷设备的防护能力有限，不承诺绝对防复制。

设备列表需支持名称、系统、绑定/最后使用时间、撤销、遗失、离职、换机流程及操作记录；撤销关联会话和受保护 API 权限。跨电脑是重新登记/迁移，不等于复制旧令牌。

### 6.2 已确认规则与后续细则

用户已确认首版：每账号最多绑定1台电脑、同时在线1台；员工换机由团队管理员审核，管理员本人由产品负责人审核，不提供自行替换已绑定设备的通道。Windows与Mac共享该账号限额。新设备登记/换机状态和审批必须由服务端核验，不能只覆盖本地设备ID或复制旧令牌。

用户后续已确认首版断网暂停团队业务、联网后恢复，不提供离线业务许可；同一电脑仅一个业务会话，新完成设备持钥登录后旧实例退出。员工换机由团队管理员审核，管理员本人由产品负责人审核。重装/遗失产生新key不能清除历史后冒充首次绑定；最高审核账号恢复首版不开放；所有权、冷却和席位转移等细则仍需后续确认。[M3A底座](DEVICE_IDENTITY_FOUNDATION.md)、[M3B正常Windows客户端](DESKTOP_DEVICE_SESSION.md)和[M3C员工/管理员换机审批](DEVICE_REPLACEMENT.md)本地已验；Mac/真实跨电脑与正式部署仍待分别完成，不能从单机多keydir推出真机迁移已验。

### 6.3 客户端验收

隔离渲染进程和特权文件/系统能力；IPC 白名单和参数验证；禁止不受信内容获得 Node/文件系统任意能力。安装、升级、卸载保留用户资料策略清楚；安装包/更新包签名与校验，失败可回退且不降级绕过权限。

Windows 原生安装/更新和 macOS Intel/Apple Silicon 兼容范围、签名、公证、Keychain/系统凭据存储、下载运行、设备迁移均分别记录实测。缺 Mac 和签名账号时只交技术候选包及待验收项，不能凭 Windows 编译代写 Mac 已通过。

## 7. 团队年订阅、席位与收款

### 7.1 权益和席位

订阅归团队、席位给成员；成员业务权限独立。订单、支付流水、订阅状态、权益版本分表/分模型。客户端不依据本机日期、跳转页或可编辑配置决定权益。

候选状态：`未开通/试用（是否提供另议）→ 生效 → 到期 → 续费恢复`；取消、退款、拒付、订单关闭分别处理。有效期采用服务端 UTC 时刻，界面按本地时区解释。提前续费通常从当前有效截止日延长、已到期从实际生效时刻起算，这是待确认商业口径，须覆盖闰年和边界时刻。

确认前不编造价格、优惠、试用天数、税率、席位上限、超额处理、增购折算、减席退款、到期宽限与资料保留期限。建议到期保留历史可读/按原权限导出和续费入口，限制新增业务；任何例外能力仍要鉴权，不能让续费入口泄露财务资料。

默认规划“到期提醒＋用户主动续费”；自动扣款是另一个需要支付能力、协议和单独授权的产品，不因年订阅自动开启。

### 7.2 官网与软件入口

已确认官网必做；“统一在官网收款、客户端跳转同一订单中心”为候选建议，待用户之后确认。无论入口选哪边，服务端只有一套团队订单与权益账本，避免双重扣费和到账不一致。

官网包括产品介绍、能力边界、价格/席位说明、Windows/Mac 下载和版本说明、帮助、账号入口、订阅/订单、主体及备案信息、隐私/服务/续费退款条款。只有真实实现并验收的功能才能写进官网宣传。

支付通道待经营主体和资质确认后选择微信/支付宝等正规商户产品；当前只做模拟网关或官方可用测试环境。生产商户审核、费率、签约和支付资质以真实申请为准。

### 7.3 支付闭环验收

服务端建单并锁定团队、商品/席位、金额/币种和年限；回调验签/解密、校验商户/订单/金额、唯一事件幂等、事务更新订单与权益；延迟通知靠主动查单/对账修复。防重复点击、重复/乱序/伪造通知、超时关闭、回调重放、退款与权益撤销不一致。支持退款申请和处理留痕；不能仅有付款按钮而无对账、异常补偿。

## 8. 数据与服务端架构方向

建议实体边界（不是已存在接口）：`User / Credential / Team / Membership / ProjectGrant / CollectionTask / Document / Session / Device / Subscription / SeatAssignment / Order / PaymentEvent / AuditEvent`。

官网、桌面客户端连接同一受信后端；服务端才拥有成员、角色、任务范围、设备和权益的可信状态。关系数据库承载事务/授权索引，私有对象存储承载获准上传的原件；实际框架、数据库、云产品和地域在 ADR 与预算确认后选择。

国内服务端是确认方向；具体哪些客户资料可上云、谁是处理者、是否私有部署、原件保存/备份/删除规则及事务所合同仍需逐项确认。研发使用合成资料，不因为用户选国内服务端就自动迁移真实客户原件。不默认向境外分析、AI或遥测服务发送资料。

迁移必须先盘点、备份、显式选择团队/项目、核对数量/哈希/公式链接、演练恢复；新后端不能破坏 UUID、历史报价快照、冻结及CAS语义。无权将 GitHub 当客户文件存储。

M4已补[合成库离线备份／恢复演练](TEAM_OFFLINE_BACKUP.md)：新目录恢复并核整库、原件、已保存版本和冻结，不更改源库、不启动在线副本。历史密码／停用／grant／设备撤销等可能倒退，不能以清空会话代替可信恢复；生产恢复、加密保管、密钥与外部存储仍属后续门槛。

## 9. UI 与易用性升级

当前阶段先保证权限相关导航、登录/设备/到期错误清晰；整体改版在核心业务和权限流程稳定后进行。

实施时采用 `redesign-existing-projects → web-design-engineer`，先读已批准的艺术方向和现有组件，若需改变品牌/核心布局再确认。先给典型页面和角色任务走查，经用户确认后推广，不一次重写全部页面。

验收包含：中文正文/表格字号、对比度、行高与密度、清晰焦点/键盘操作、缩放与窗口尺寸、长表单/长表格、错误恢复、空/加载/无权限/到期状态、连续保存反馈、数据不丢、Win/Mac 字体差异。用“采集任务完成、经理定位项目、合伙人查看概览、管理员续费”等合成任务测可用性；具体色值与字号此时不抢先锁定。
