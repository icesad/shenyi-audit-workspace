# 团队底稿桌面入口合同

本合同补充 WORKPAPER_DESKTOP_CONTRACT.md，适用于 M4Q 正常桌面候选。当前用户已确认完整底稿包显式迁入；实际客户资料迁入仍另行授权。专业复核、新冻结、重开及报告签发仍由米老师明确。

## 用户流程与权限

经理／合伙人只列出当前团队内可授权或已获权项目。实习生／助理不显示底稿入口，直接调用也必须由服务端拒绝。负责人身份只允许配置授权，不自动得到资料；负责人验证当前密码后，分别授予自己或本项目符合资格的经理／合伙人查阅、填写、导出权。填写和导出都要求同时有查阅权。

首次迁入只接受系统文件选择器选出的旧版显式完整包。主进程私有保存路径与原包字节，Worker核验，页面只接收摘要、SHA和随机句柄；负责人核对原包、已保存填写、既有冻结并验证密码后提交。页面不允许传入路径／原件／任意请求地址。包不匹配当前正式来源、已有团队底稿或权限变化时拒绝。

查阅展示保存版本、原件摘要和 Office 原表。Excel复用旧原表布局渲染；无布局时显示有界40行×12列分页，隐藏行列、公式、链接、数组和非准入锚点不开放填写。Word复用已验证native model或旧DOC纯文本段落。只读和既有冻结仍显示已保存填写，不伪造新冻结；正文按纯文本展示，不执行宏、公式、字段或外部链接。

当前head内可填写位置保存为新不可变版本；旧版本保持只读。未保存内容须明确保存或丢弃后才能导航。权限、团队、账号、设备或窗口变化清除旧内容；晚到响应不能重新呈现。导出固定所选已保存版本和对应head／来源／SHA／授权修订，原生文件工作流沿用双权、流式核验、发布后实际目标复核。

## IPC与页面边界

旧135个API／channel保留名称、映射和顺序，尾部仅增加20个具名底稿方法；未开放getWorkpaperOriginal或通用fetch／文件接口。open返回随机viewId并固定teamId和可选projectId；切换项目新开view，随后每个项目调用必须与固定目标一致。来源及导出取消句柄须属于当前view。所有handler先验证当前主窗口、主frame身份和严格本地origin，再处理无getter／原型／二进制的被动JSON。

仅增加5个self资产：workpapers.js、workpapers.css、workpaper-sheets.js、workpaper-original-sheet.js、workpaper-original-word.js。保留sandbox、contextIsolation、禁用renderer Node和原connect-src none CSP，不因渲染放宽策略。读取／变更在await前后核对view及真实账号／设备租约。关闭、导航、进程消失和dispose清理私有来源、读取和未发布导出。

每项已发保存／迁入都有永久原操作编号。未解决的pending／unknown不会因历史列表超过20项而被淘汰，只有已解决历史可以截尾。明确收到saved／imported回执后，后续只读刷新失败不改变已知提交终态。结果未知只允许按原编号只读查询；404不证明取消。分块上传可在核对原状态后明确续传，未知commit不重发。授权结果未知要求刷新实际权限，不编造操作ID。已经发布或发布状态未知的导出不能假报取消或自动重复保存。页面保留编号，不在localStorage／sessionStorage保存底稿。

底稿请求时限按精确路由区分：原件／record／form及填写90秒、首次发布180秒、流式导出1800秒；其他认证、控制、分块及未知路由仍15秒。它们是每个请求的预算，显式取消、权限与正文响应限制沿用。
