# 采集工作区正式业务确认与来源关联

本功能让当前项目负责人核验已保存的中标／立项来源，并以当前密码确认来源与采集工作区的关联。系统保存确认人、确认时间、来源摘要及不可变回执。来源一致性检查不能证明现实中的中标事实或实时最新状态；这一步也不代表审计报告签发。

## 正常操作

1. 经理或合伙人打开自己负责的采集工作区。已有任务、资料采集权限和原件继续沿原规则使用。
2. 在正式业务确认区域选择已保存的正式立项来源 JSON。文件须先通过旧版原编号、中标引用和立项记录的一致性检查。
3. 核对当前工作区 W、原业务身份 Q、名称、业务编号、首次中标／立项引用中标／最新已保存中标三个时间，以及来源 SHA。报价金额只供核对，不自动成为最终项目金额。
4. 明确勾选来源业务核验和关联确认，输入自己的当前密码，再提交一次。界面只显示最小摘要，文件路径和完整来源不下发到页面。
5. 查看服务器回执和重新读取的项目状态。采集工作区显示“负责人已业务确认正式立项”；创建回执仍忠实记录创建时尚未立项。

选择文件时使用其当时的私有快照。之后修改磁盘文件不会改变当前待确认来源，需要重新选择。取消、切换账号／设备、页面导航或关闭会清除私有快照。

只有当前有效本团队项目负责人可以读取详细来源和回执或发起确认。职级、项目阅读权、技术管理员身份均不能替代负责人资格；管理员兼任业务身份仍须已有批准。冻结时只读，归档后拒绝访问。

## 提交结果未知

保留界面显示的原确认编号，联网并正常恢复设备会话后，使用“只读查询回执”。系统不会自动重复提交；查询暂时返回不存在，也不能据此断定先前在途请求绝不会完成。离开后重新打开同一工作区仍可输入原编号查询。

已确认的工作区和来源不能通过本入口改绑、覆盖、撤销或重复合并。后续业务变化需要另行设计追加修订流程。

## 数据和权限

团队采集资源 W 与旧报价／立项业务身份 Q 分别保存；不重命名 UUID，不移动文件，不改源 JSON。一次确认只增加不可变来源与业务确认记录，并将该工作区元数据版本推进一次。原权限、任务、指派、原件、历史、创建人及创建回执保持。

资料清单模块仍使用独立五项权限，且目前要求其包内身份与团队项目身份一致。W／Q 的资料适配属于下一单项；本次业务确认后仍不能直接打开该模块。旧版同 UUID 正式项目的资料路径保持原规则。
