# ADR 0001：团队模式运行时与可信边界

日期：2026-11-15；阶段：M1；状态：**选择一个工程验证候选，尚未通过双平台兼容/业务验收，不是生产选型批准**。

关联：[团队产品需求](../TEAM_PRODUCT_REQUIREMENTS.md)、[阶段路线图](../COMMERCIALIZATION_ROADMAP.md)、`TEAM-M1`。

## 1. 选择与依据

本轮以 **Electron 桌面壳＋独立 Node.js 24 服务端**作为下一阶段的单一验证候选。生产关系数据库、私有对象存储、阿里云产品和规格尚未选择。Tauri 保留备选，不同时实现两套桌面产品。

这是结合当前代码作出的工程判断：应用主体为平铺 `dist/` 中的 HTML/JS/CSS，已有大量浏览器解析器、Worker 和 Chromium 回归；优先验证 Chromium 运行环境能否保持原件处理行为，减少先改写前端的范围。网页能打开不证明 Electron 打包后兼容。`dist/` 是现有源码，不能当构建垃圾删除。

| 候选 | 当前收益判断 | 必须验证或拒绝的条件 |
|---|---|---|
| Electron，先验证 | 可复用现有前端与 Chromium 测试经验；桌面特权可集中到小型主进程边界 | 禁止为兼容而关闭隔离/sandbox或开放任意IPC；测安装体积、空闲/解析内存和启动时间；关键原件处理、资源协议或双平台发行不可达时复审 |
| Tauri，备选 | 官方 `frontendDist` 支持递归嵌入已有静态资源，以 `index.html` 为入口，能够避免先重写React/Vite | 系统WebView、原件读取器、下载/Worker兼容及原生构建链另验；不能仅凭包体预期更小就改方案；若转用则另开有证据的ADR修订 |

Electron/Tauri版本在真正安装时从官方支持状态与锁文件选定，写明版本和许可证；本ADR不固定未经实际核验的版本，不安装依赖。

## 2. 当前架构事实

- `server/profile.mjs` 明确只处理平台账号资料，`authentication:'platform'`、`business:'device-shared'`、`phoneLoginEnabled:false`；它没有独立密码登录或业务团队权限。
- `hosting-server/app/api/account/route.ts` 使用 `getChatGPTUser()`；`hosting-server/app/chatgpt-auth.ts` 依赖平台注入身份头。独立部署后不能把互联网客户端提交的同名头当作可信身份。
- `hosting-server/db/schema.ts` 当前仅有账号资料表；不能将其描述成团队、设备、订单数据库已齐备。
- `dist/project-workspace-store.js` 使用固定的浏览器业务库并按项目UUID定位；CAS和本机冻结可保留，但不能充当服务端授权。
- `scripts/serve.mjs` 是固定本机origin的静态预览，不是未来团队业务后端或生产部署入口。

新团队模式与旧本机模式使用不同的数据适配入口和存储命名空间，界面明确模式。未经授权不把旧IndexedDB写到新服务、不猜测所属账号/团队，也不借新账号功能修改原站点登录方式。

## 3. 目标运行边界

```text
桌面隔离渲染器：被授权任务UI、原件解析
       │ 限定IPC / 有认证的API请求
桌面主进程：受控文件选择/导出、系统保护存储、设备签名
       │ HTTPS（生产）
独立团队服务：身份 → 团队/项目/任务授权 → 设备/权益约束
       ├─ 关系库：用户、会话、成员、指派、版本、设备、订阅、订单、留痕
       └─ 私有对象存储：获准上云的原件与版本；每次访问仍鉴权

官网：介绍、下载、帮助、账号/订单入口 → 同一身份及订单/权益服务
```

### 各边界只承担自己的职责

| 边界 | 可信判定 | 不可信输入/不能代替的能力 |
|---|---|---|
| 身份 | 服务端验证密码/恢复凭据、有效会话、用户状态 | 自填userId、资料手机号、角色、平台身份头或任意客户端声明 |
| 授权 | 活跃成员、角色允许的能力、团队/项目/任务关系、字段/附件权限及资源状态 | 隐藏菜单、客户端“已授权”或“合伙人”标志；高职级不等于跨团队通行 |
| 设备 | 登记公钥、一次性挑战、账号/设备/会话关联与撤销状态 | MAC地址、硬件指纹、可复制设备ID；电脑绑定不替代账号/业务权限 |
| 订阅/席位 | 服务端订单与权益事务、可信支付结果、席位分配 | 本机时钟、前端付款成功页、管理员付款身份；付费不扩大审计数据权限 |
| 文件 | 原件身份、团队/任务关联、明确的读/预览/下载权限及当前授权 | 只知道附件ID/URL、猜中对象键或被指派任务；整份原件可能超出采集范围 |

请求处理、SQL查询、搜索索引、统计和导出均必须携带当前授权范围；先过滤再计数/分页/返回，不能下发完整项目后在客户端删字段。无权限详情与未知资源返回不泄露存在性的结果；异常不输出SQL、凭据、他队名称或内部路径。共享缓存、文件票据和后台任务也受同样范围约束。

## 4. M1数据库实验与生产选型分离

本轮使用 Node 24 的 `node:sqlite` 执行内存合成数据库和实际参数化SQL，验证授权模型、关系约束和查询出口。Node 24.22.1官方文档标注其为 Stability 1.2（Release candidate）；`DatabaseSync`的API同步执行。它适合当前无需新依赖的可重复实验，这不构成已完成生产容量/可靠性评估。[Node 24.22.1 SQLite官方文档](https://nodejs.org/download/release/v24.22.1/docs/api/sqlite.html)

生产候选采用支持事务、约束、备份恢复的关系数据库；需在部署/预算明确后比较托管PostgreSQL/MySQL等与独立SQLite部署的并发、备份、故障恢复、运维及授权实现成本，再做选择。本轮不购云、不把服务端数据库交给客户端、不借数据库产品名声称天然租户隔离。

仓储接口须把查询范围作为必需条件；受信会话和授权读取跟随数据库当前状态，不能把客户端提供的上下文作为长期权限快照。关系库与对象存储不跨事务时，采用暂存、确认提交及可重试清理流程，避免元数据存在但原件丢失或越权公开。实现前发现适配器的实际错误与事务语义，不能只测返回固定成功的Mock。

## 5. 桌面特权、密钥与升级

1. 打包资源走受控应用协议，导航、新窗口、外部链接和权限请求按白名单处理；API基址独立配置。旧本机origin不自动沿用为桌面安全域。
2. 渲染器显式 `nodeIntegration:false`、`contextIsolation:true`、`sandbox:true`；原件解析在隔离渲染器/专用沙箱中，主进程不解析不可信Office/PDF。preload只暴露小型业务方法，校验IPC发送方和参数，不暴露通用 `exec`、任意路径读写或完整 `ipcRenderer`。[Electron安全建议](https://www.electronjs.org/docs/latest/tutorial/security)
3. 文件读取仅来自用户明确选择的范围；导出限制目标和文件名。失败保留原始字节/哈希，不覆盖源文件。系统文件对话框、下载、Worker、Blob、字体与IndexedDB须在实际应用协议下验证。
4. 设备安装实例生成独立密钥，服务端登记公钥、验证挑战并关联会话；私钥使用操作系统保护存储，设备列表/撤销/重绑由后端约束。硬件指纹仅为最小化、已披露的风险信号。尚未证明硬件保护/私钥不可导出；被攻陷设备和本机管理员的风险必须明示。
5. 用户设备私钥、更新签名私钥、Windows/Mac发行证书三者分开管理；发行秘密不打进安装包、不进Git、不进入日志。正式下载/升级只接受受信签名/校验，升级不得绕过设备/权益/授权；更新失败保留恢复路径，旧客户端访问服务端仍按当前权限处理。
6. Mac签名、公证及Keychain连续性须实机验证；官方说明未签名或签名不一致可影响 `safeStorage`/Keychain，Squirrel.Mac自动更新依赖签名。Windows证书/签名服务按真实主体资格选择，不保证签名后每台机器都无安全提示。[Electron发行签名](https://www.electronjs.org/docs/latest/tutorial/code-signing)
7. 若改用Tauri，其更新插件要求更新验签，签名不能关闭；更新包验签也不能替代OS代码签名，生产更新地址保持HTTPS。[Tauri更新插件](https://v2.tauri.app/plugin/updater/)

## 6. 下一M2最小纵向闭环

以两个合成团队、四角色账号、两个项目和任务/附件范围为样本，先接通：

`独立测试账号登录 → 加入团队 → 受控人员指派采集任务 → 实习生/助理只见自己的最小任务 → 明确选择合成文件 → 服务端授权保存 → 返回提交状态 → 撤销任务/账号后后续访问拒绝`。

M2不把既有本机应用全量接云：先新增团队模式入口及适配层，经理/合伙人的尚未确认能力默认拒绝。密码登录标识、邀请/恢复和团队归属的正式规则确认前，可用清楚标识的本地测试账号验证技术闭环；测试身份不能被当作生产注册流程。设备接口预留明确认证边界，M3必须在首版对外交付前接入，不用无绑定版本冒充首版完成。

### 实验步骤与结束证据

| 顺序 | 动作 | 结束证据 |
|---|---|---|
| 1 | 在独立桌面目录锁定一个候选版本、受控协议及安全配置，载入现有dist | 实际版本/命令/日志，拒绝远程导航和非法IPC；无业务源码重写 |
| 2 | 运行合成原件导入、预览、导出/下载、Worker/Blob/字体、IndexedDB与保存重启 | 每类样例的原件哈希、实际结果和差异；不能用“窗口打开”替代 |
| 3 | 连接隔离本地团队后端，运行两个团队四角色的列表/搜索统计/详情/附件/导出允许与拒绝测试 | 后端实际响应/SQL测试和不泄露正文/元数据的证据；角色/任务/会话撤销即时生效 |
| 4 | Windows标准用户环境安装、启动、导入、退出再登录；验证系统凭据与资料保留 | Windows原生记录；打包/签名/升级尚缺的项目分列 |
| 5 | 获取经授权Mac环境后重复步骤1–4，分别记录Intel/Apple Silicon实际范围 | macOS原生截图/日志、签名公证/Keychain证据；未具备前写未验收 |
| 6 | 明确记录候选通过/失败和下一步 | 保留一个候选；关键兼容失败或只能放宽安全配置才能运行时，停止该方案并据证据评估Tauri，不无限试错 |

本轮M1的结束证据为ADR、可执行服务端授权实验及独立复核；不包含“桌面兼容/独立密码/设备绑定/支付已完成”的结论。

## 7. 迁移和仍需决定的规则

旧UUID、报价快照、CAS、冻结、原件及公式链接保持。迁移另做盘点→仓库外授权备份→选择团队/项目→导入演练→数量/哈希/版本核对→空环境恢复验证；不因更换账号或设备自动搬数据，旧浏览器数据清理另需明确指令。退出/撤销不保证追回已经合法下载的原件；缓存与离线策略须先确认。

待产品负责人决定：账号标识及恢复、多团队/所有权、每人电脑和同时在线数、换机和离线政策、价格/席位/到期保留与退款、经营主体/省份/预算、哪些真实资料允许上云、官网收款入口。待米老师确认：核对/关门、底稿/报告、经理/合伙人及签发细目。未知项只阻断依赖操作，安全的合成实验继续。

官方资料核验日期2026-11-15；以上桌面候选的兼容收益是本项目推断，不是厂商对审易的保证。另见 [Tauri静态资源配置](https://v2.tauri.app/reference/config/#frontenddist)。
